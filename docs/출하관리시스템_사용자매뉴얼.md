# 1. 시스템 개요

## 1.1 시스템 소개

PTLPSM(출하관리 시스템)은 공공조달 물류/출하 업무를 통합 관리하는 시스템입니다. 발주부터 납품완료, 자금 정산까지 전체 프로세스를 지원합니다.

- **관리자 웹**(PC): 발주·출하·납품·자금 등 모든 관리 업무. 주소 체계는 `/admin/...`
- **모바일 납품확인**(스마트폰): 현장 인수자/서명자가 로그인 없이 URL로 접속. 주소 체계는 `/m/delivery/{토큰}`

> 📷 [스크린샷: 로그인 화면 및 관리자 메인 대시보드 — 좌측 메뉴 + 상단 사용자/알림]

### 주요 특징

| 기능 | 설명 |
|------|------|
| **PDF 자동 추출** | 납품요구서 PDF를 업로드하면 AI/OCR로 정보 자동 추출 |
| **모바일 납품확인** | 현장에서 스마트폰으로 서명, 사진 촬영, GPS 위치 기록 |
| **다중 서명** | 현장소장 + 감리원 서명을 통한 승인 체계 |
| **자금 추적** | 선급금 → 기성금 → 잔금 → OEM 지급 전체 관리 |
| **문서 자동 생성** | 납품확인서, 납품완료계, 선급금 문서 등 자동 생성 |

## 1.2 전체 업무 흐름

이 시스템에는 **서로 다른 두 개의 축**이 흐른다. 하나는 수요기관에게 받는 돈(매출),
다른 하나는 제조사에게 주는 돈(원가·지급)이다. 두 축은 **출하**에서 만난다.

### 축 1 — 고객(수요기관) 방향 : 매출

```
┌─────────┐   ┌─────────┐   ┌─────────┐   ┌─────────┐   ┌─────────┐   ┌─────────┐
│납품요구 │→  │  출하   │→  │  운송   │→  │  납품   │→  │납품완료 │→  │  자금   │
│  등록   │   │  등록   │   │  배차   │   │  확인   │   │   계    │   │  정산   │
└─────────┘   └─────────┘   └─────────┘   └─────────┘   └─────────┘   └─────────┘
     │             │             │             │             │             │
     ▼             ▼             ▼             ▼             ▼             ▼
납품요구서    출하지시서      운송장      모바일 서명     3종 PDF      선급/기성
 PDF 추출        발행          발행        사진 촬영       생성        잔금 수금
```

기준 금액은 **품대계(`orders.item_total_amount`)** 다. 계약수량 × 단가이며,
뒤에서 손실이 발생해도 **이 금액은 바뀌지 않는다.**

### 축 2 — 제조사(OEM) 방향 : 원가와 지급

```
┌─────────┐   ┌─────────┐   ┌─────────┐   ┌─────────┐   ┌─────────┐
│ 제조사  │→  │  재고   │→  │  출하   │→  │  월별   │→  │   OEM   │
│  발주   │   │  입고   │   │  원가   │   │매출원장 │   │  지급   │
│         │   │         │   │ 스냅샷  │   │         │   │         │
└─────────┘   └─────────┘   └─────────┘   └─────────┘   └─────────┘
     │             │             │             │             │
     ▼             ▼             ▼             ▼             ▼
생산자 지정   창고별 재고     그 시점     지급예정액     지급 요청
가공비 입력    (㎡ 단위)     원가 고정     + 부가세     확인 → 완료
```

두 축이 만나는 곳이 **출하**다. 같은 출하 한 건이 고객에게는 매출을,
제조사에게는 지급을 만든다.

### 데이터 관계도

```
납품요구(Order) ──── 1:N ────→ 출하(Shipment) ──── 1:1 ────→ 운송(Transport)
    │                            │                              │
    │                            └──────────── 1:1 ─────────────┤
    │                                                           ▼
    │                                                    납품확인(Delivery)
    │                                                           │
    │                                                           ▼
    │                                                    인수증 PDF 생성
    │
    ├──── 1:N ────→ 기성차수(Baseline) ──→ 납품확인서 / 사진대지 PDF
    ├──── 1:1 ────→ 납품완료계(DeliveryDone) ──→ 3종 PDF
    └──── 1:1 ────→ 자금(Fund)
                      ├── 선급금 (1회)
                      ├── 기성금 (N회) ←── 기성차수와 연결
                      └── 잔금 (1회)

제조사 발주(PurchaseOrder) ──── N:M ────→ 출하(Shipment)
    │                                        │
    │  (purchase_order_shipment_links)       ▼
    │                                   손실(LossAdjustment)
    ▼                                        │
  재고(Inventory) ←──── 소진(Consumption)    └──→ 보전 발주 → 보전 출하
```

| 관계 | 비율 | 의미 |
|------|------|------|
| 납품요구 → 출하 | **1:N** | 납품요구 1건을 여러 번 나눠 출하 |
| 출하 → 운송 | **1:1** | 출하 1건당 운송장 1건 |
| 운송 → 납품확인 | **1:1** | 운송 완료 시 납품확인 1건 |
| 납품요구 → 기성차수 | **1:N** | 기성금 분할 청구 |
| 납품요구 → 자금 | **1:1** | 납품요구별 자금 관리 |
| **제조사 발주 → 출하** | **N:M** | 발주와 출하는 1:1이 아니다. 한 발주가 여러 출하에 걸치고, 한 출하에 여러 발주가 물릴 수 있다 |
| **출하 → 손실** | **1:N** | 한 출하에서 품목별로 손실이 날 수 있다 |

> ⚠️ **제조사 발주와 출하가 1:1이 아니라는 점이 중요하다.**
> 그래서 손실이 생겨도 발주서 수량을 고치지 않는다. 고치면 다른 출하까지 흔들린다.

### 재고 흐름

재고는 **창고별 × SKU별**로 관리되고, 단위는 **㎡** 다 (**1매 = 2㎡**).

```
            ┌──────────────── 들어오는 것 ────────────────┐
            │                                             │
   제조사 발주 입고                              창고 이동(+)
      (PO / INBOUND)                          (TRANSFER / TRANSFER_IN)
            │                                             │
            ▼                                             ▼
        ┌─────────────────────  재고(Inventory)  ─────────────────────┐
            │                      │                      │
            ▼                      ▼                      ▼
      운송 출고                재고 소진 확정          창고 이동(−)
  (TRANSPORT / OUTBOUND)   (CONSUMPTION / ADJUST)  (TRANSFER / TRANSFER_OUT)
      = 고객에게 나감         = 출하로 안 잡히는 출고
```

| 경로 | 기록 유형 | 언제 |
|------|-----------|------|
| 제조사 발주 입고 | `PO` / INBOUND | 발주 입고 처리 시 |
| **운송 출고** | `TRANSPORT` / OUTBOUND | **출하 등록이 아니라 운송(배차) 단계에서 빠진다** |
| 창고 이동 | `TRANSFER` / TRANSFER_IN·OUT | 창고 간 이동 |
| 재고 소진 | `CONSUMPTION` / ADJUST | 소진 **확정** 시 (DRAFT 상태에서는 안 빠짐) |
| 손실 조정 | `LOSS` / ADJUST | 손실 등록 시 담당자가 선택한 경우만 |
| 수동 조정 | `MANUAL` / ADJUST | 재고 실사 보정 등 |

> ⚠️ **재고가 빠지는 시점은 출하 등록이 아니라 운송이다.**
> 출하만 등록하고 배차하지 않으면 재고는 그대로 남아 있다.

### 원가·지급 흐름

원가는 **한 번 정해지면 그 시점 값으로 고정(스냅샷)** 된다. 나중에 원가표를 고쳐도 과거 건은 바뀌지 않는다.

```
 제조사 원가 (적용기간 구간표)
        │   ← 기준일의 구간을 찾아 가져온다 (as-of)
        ├──────────────► 발주 등록 시점 스냅샷
        │
        └──────────────► 출하 등록 시점 스냅샷  ← 실질 기준
                                │
                                ▼
                      OEM 월별 매출원장
```

**지급 예정 공급가액** 은 이렇게 만들어진다.

| 구성 | 부호 | 출처 |
|------|------|------|
| 발주 합계 | + | 그 달 발주의 원가 × 수량 |
| 비출하 재고 소진 | **+** | 품질관리 발송 / 리드파워 계약 등 |
| 운송비 | **+** | 운송비 유형이 «소량 주문 시 OEM에 지불» 인 건만 |
| 가공비 | **+** | 발주 등록 시 입력한 가공 비용 |
| 손실 차감 | **−** | 제조사 귀책 분담분 |

```
지급 예정 공급가액 = 발주 합계 + 비출하 소진 + 운송비 + 가공비 − 손실 차감
부가세          = 공급가액 × 10%
합계(VAT 포함)   = 공급가액 + 부가세
```

> 지급 요청을 넣으면 **서버가 원장을 다시 계산해서** 금액을 정한다.
> 화면에 보이는 지급 예정액과 실제 요청 금액이 어긋나지 않는다.

### 두 축이 어긋나는 지점 — 손실

출하한 수량과 현장에 도착한 수량이 다를 때, 두 축이 갈라진다.

| | 고객 축 (매출) | 제조사 축 (원가·지급) |
|---|---|---|
| 계약수량 | **그대로** | — |
| 청구 금액 | **그대로** (품대계) | — |
| 고객 서류 | **그대로** (손실 표기 안 나감) | — |
| 납품률 · 잔여 | 계산할 때만 손실분 차감 | — |
| 지급액 | — | 제조사 부담분만큼 **차감** |
| 재고 | — | 담당자가 선택한 경우만 조정 |

부족분은 **보전 발주 → 보전 출하** 로 정상 프로세스를 그대로 타서 메운다.
무상출하 같은 별도 개념을 쓰지 않는다.

## 1.3 사용자 역할

권한은 역할 코드(roleCode) 기준으로 부여됩니다. **시스템관리자(SYSTEM_ADMIN)** 와 **리드파워담당자(LEADPOWER_MANAGER)** 는 전체 기능에 접근할 수 있고(전체 접근 권한), 그 외 역할은 담당 업무로 제한됩니다. 시스템관리 메뉴(시스템 설정·접근로그·방문통계 등)는 **SYSTEM_ADMIN 전용**입니다.

| 역할 | 코드 | 주요 업무 | 접근 범위 |
|------|------|----------|----------|
| 시스템 관리자 | SYSTEM_ADMIN | 사용자/권한 관리, 시스템 설정, 통계 | 전체(시스템관리 포함) |
| 리드파워 담당자 | LEADPOWER_MANAGER | 발주/출하/납품/자금 관리 | 전체(시스템관리 제외) |
| 영업 담당자 | SALES | 수주/견적/영업 관리 | 담당 업무 |
| 현장 소장 | SITE_MANAGER | 납품확인·기성 서명 | 모바일 서명 |
| 현장 감리원 | SITE_INSPECTOR | 납품확인 검수·서명 | 모바일 서명 |
| 운송 담당자 | DRIVER | 배송 상태 업데이트 | 운송 |
| 제조사 담당자 | OEM_MANAGER | 자기 회사의 발주·재고·소진·손실·받을 돈 확인 | 자기 회사 자료만 |

### 제조사 담당자(OEM_MANAGER)가 할 수 있는 일

제조사는 **"내가 만들어 보낸 것"과 "받을 돈"** 을 다룹니다. 납품요구·납품요청은 리드파워와 수요기관 사이의 계약 정보라 제조사 자리가 아닙니다.

| 메뉴 | 조회 | 등록·수정 | 삭제·확정 |
|------|:----:|:---------:|:---------:|
| 발주서관리 | ✅ | ❌ | ❌ |
| 재고현황 | ✅ | ❌ | ❌ |
| **재고 소진관리** | ✅ | ✅ | ❌ **확정·취소·삭제는 관리자** |
| **손실관리** | ✅ | ✅ | ❌ **정산·삭제는 관리자** |
| 월별 매출원장 | ✅ | ❌ | ❌ |
| 운송관리 | ✅ | ✅ | ❌ |
| OEM 대시보드 | ✅ | — | — |

> **돈이 확정되는 지점만 관리자에게 남깁니다(2026-09-16).** 소진을 확정하면 재고가 빠지고 그 제조사 지급액이 **가산**되고, 손실을 정산하면 지급액이 **차감**됩니다. 제조사가 스스로 손실을 지우면 받을 돈이 늘어나므로, 올리는 것까지는 열고 확정·삭제는 리드파워가 합니다.

> **운송비 원장은 제조사에게 보이지 않습니다.** 리드파워가 운송사에 내는 돈이라 제조사와 무관하고, 열면 거래처 운송 단가가 드러납니다.

> **자기 회사 자료만 보입니다.** 재고·소진·손실·원장 모두 소속 제조사로 걸러집니다.

> 메뉴별 노출/접근 권한은 **기초정보 → 메뉴권한(`/admin/basic-info/menu-auth`)** 에서 역할별로 관리합니다. (역할 코드 명칭이 코드와 다를 수 있어 일부는 `(확인 필요)`)
>
> ⚠ **권한은 두 겹입니다.** 메뉴권한 화면(보이는 것)과 시스템 내부 규칙(실제 호출 가능 여부)이 따로 있습니다. 메뉴권한만 열면 **메뉴는 보이는데 눌렀을 때 막힐 수 있습니다.** 권한을 바꿔야 한다면 개발 담당자와 함께 확인하세요.

## 1.4 용어 정의

### 1.4.1 핵심 엔티티(업무 단위)

| 용어 | 영문/테이블 | 설명 | 다른 표현 |
|------|------------|------|-----------|
| 발주 | Order / orders | 공공조달 계약에 따른 물품 납품 요청 단위 | 납품요구·수주·계약 |
| 출하 | Shipment / shipments | 창고에서 현장으로 물품을 보내는 단위 | 배송·출고 |
| 운송 | Transport / transports | 출하 물품의 운송 정보(차량·기사) | 배차·운송장 |
| 납품확인 | Delivery / deliveries | 현장에서 물품 인수를 확인하는 절차 | 인수·수령확인 |
| 납품사진 | DeliveryPhoto | 납품 현장 증빙 사진 | - |
| 기성차수 | Baseline / baselines | 기성금 청구를 위한 납품 완료 단위(1·2·3차…) | 기성·차수 |
| 기성차수품목 | BaselineItem | 기성 차수의 품목별 수량/금액 스냅샷 | - |

### 1.5.2 기성금 청구 프로세스

**납품확인이 완료된 출하**만 기성금 청구에 포함할 수 있습니다.

```
납품확인 완료된 출하 확인 (인수증 서명 완료분만)
        ▼
기성 차수 생성 (청구할 출하 선택 → 품목별 수량/금액 스냅샷)
        ▼
서명 URL 발송 (현장소장 + 감리원에게 LMS/SMS)
        ▼
현장소장 서명(PARTIAL_SIGNED) → 감리원 서명(SIGNATURE_COMPLETED)
        ▼
납품확인서 + 사진대지 PDF 자동 생성 (차수 상태: CONFIRMED)
        ▼
기성금 수금 확인 (입금일·입금금액 확인 후 PAID)
```

### 1.5.3 선급금 vs 기성금 vs 잔금

| 구분 | 신청 시점 | 신청 조건 | 금액 기준 | 서명 필요 |
|------|----------|----------|----------|----------|
| **선급금** | 첫 출하 전후(계약 초기) | 출하 여부 무관, **1회만** | 계약금액 × 비율(70%) | X |
| **기성금** | 납품 진행 중(여러 차수) | 납품확인 완료된 출하 | 실제 납품수량 × 단가 | O (현장소장+감리원) |
| **잔금** | 납품완료 후 | 납품완료계 완료 | 계약금액 − 선급금 − 기성금누계 | X |

**자금 흐름 예시:**
```
계약금액: 1억원
    ├─→ 선급금: 7천만원 (70%)        ←── 첫 출하 전 신청
    ├─→ 1차 기성금: 1천만원           ←── 1·2차 출하 납품확인 완료 후
    ├─→ 2차 기성금: 1천만원           ←── 3·4차 출하 납품확인 완료 후
    └─→ 잔금: 1천만원 (1억−7천−1천−1천) ←── 납품완료계 서명 완료 후
```

### 1.5.4 납품완료 시 생성 서류

## 1.7 공통 검색 — 기간(날짜) 조건

목록 화면의 **기간 검색은 전 화면이 같은 달력**을 씁니다. 출하·운송·납품·발주서·통계·문자·로그 등 어디서든 조작 방법이 같습니다.

### 기본값은 "1년 전 ~ 오늘"

화면을 열면 기간이 **1년 전부터 오늘까지**로 잡혀 있습니다. 예전에는 화면마다 1개월·3개월·7일·빈칸이 뒤섞여 있어서, 분명히 등록한 자료가 목록에 없는 것처럼 보이는 일이 있었습니다. 이제는 전부 1년으로 통일했습니다.

> **1년보다 오래된 자료를 찾을 때**는 달력에서 시작일을 직접 더 앞으로 당기면 됩니다. 과거 실적을 일괄로 옮겨 담는 중이라면 기간을 넉넉히 벌려 놓고 작업하세요.

### 달력 사용법

| 하고 싶은 것 | 조작 |
|---|---|
| 기간 고르기 | 입력칸을 누르면 달력이 열립니다. **시작일 → 종료일** 순서로 두 번 누르면 됩니다 |
| 먼 과거로 이동 | 달력 위쪽의 **연도 / 월** 을 눌러 바로 선택합니다 (화살표를 계속 누를 필요 없음) |
| 시작월·종료월 함께 보기 | 달력이 **두 개** 나란히 열리고, 각각 따로 움직입니다. 왼쪽에 시작월, 오른쪽에 종료월을 띄워 놓고 고르면 됩니다 |
| 자주 쓰는 기간 | 달력 옆 **[1개월] [3개월] [6개월] [1년] [올해]** 버튼을 누르면 한 번에 잡힙니다 |

> 📷 [스크린샷: 기간 검색 — 두 달 달력 + 프리셋 버튼]

### 날짜 기준은 한국 시간(KST)입니다

시스템은 모든 시각을 내부적으로 세계표준시(UTC)로 저장하고, **화면에 보여줄 때만 한국 시간으로 바꿉니다.** 검색에서 고르는 날짜도 한국 시간 기준입니다.

즉 **목록에 보이는 날짜 = 검색에 쓰는 날짜** 가 항상 일치합니다. 종료일에 고른 날짜는 **그날 하루를 포함**합니다(종료일을 오늘로 두면 오늘 등록한 것까지 나옵니다).

> **2026-09-17 이전 버전을 쓰셨다면** 일부 화면에서 **오전 9시 이전에 등록한 자료가 전날 것으로 보이거나, 조회 결과에서 빠지는** 문제가 있었습니다. 접근로그·문자 히스토리·출고요청·오류게시판·자금관리·재고 입출고이력·사용자관리가 해당했고, 현재는 모두 바로잡혔습니다. 과거에 남긴 자료의 날짜 표시도 함께 정정됩니다.

## 2.1 발주(납품요구) 목록 조회

### 접근 경로
- **메뉴**: 발주관리 → 발주목록
- **화면 주소**: `/admin/order/list`

> 📷 [스크린샷: 발주 목록 화면 — 상단 통계 카드 4개 + 검색줄 + 트리 목록 테이블]

### 화면 구성

**① 상단 통계 카드 (4개)** — 현재 검색 조건 기준으로 자동 집계됩니다.

| 카드 | 의미 |
|------|------|
| 총 납품요구 | 조회된 발주 건수 |
| 금월 납품요구 | 이번 달 납품요구일자 기준 건수 |
| 총 납품요구금액 | 조회 결과의 총 계약금액 합계 |
| 총 예상 원가금액 | 품목 원가 기준 예상 원가 합계 |

**② 검색줄** · **③ 목록 테이블(트리 구조)** 로 구성됩니다.

발주 목록은 **트리 구조**로 표시됩니다.
- **기준(본)계약**: 최상위 행. 왼쪽 화살표(▶/▼) 버튼으로 하위를 펼치고 접습니다.
- **변경계약 / 추가계약**: 본계약 하위에 들여쓰기되어 표시되고, 본계약 행 우측에 **하위 계약 개수 배지**가 붙습니다.

목록 컬럼(좌→우): **No · 납품요구번호 · 납품요구일자 · 수요기관 · 담당자 · 사업명 · 상태 · 건설사 · 총계약금액 · 등록일자**

### 검색 조건

| 검색 항목 | 입력 방식 | 설명 |
|-----------|-----------|------|
| 납품요구일자 | 시작일 ~ 종료일 (달력) | 납품요구일자 기준 기간 |
| 수요기관 | 텍스트 (`수요기관명`) | 발주처 기관명 부분일치 |
| 검색어 | 텍스트 (`프로젝트명, 담당자명`) | 사업명 또는 담당자명으로 검색 |
| 상태 | 드롭다운 | 전체 / 진행중 / 완료 / 취소 |

> 입력 후 **Enter** 키 또는 우측 상단 **[검색]** 버튼으로 조회합니다.

### 단계별 조작 — 조회하기

1. 발주관리 → 발주목록으로 이동합니다.
2. 검색줄에서 기간·수요기관·검색어·상태 중 필요한 조건을 입력합니다. (조건 없이 조회하면 전체가 표시됩니다.)
3. 상단 우측 **[검색]** 버튼을 누릅니다. (검색 중에는 버튼에 회전 아이콘이 표시됩니다.)
4. 결과 테이블 우측 상단의 **[10개씩 / 20개씩 / 50개씩]** 으로 페이지당 표시 개수를 바꿀 수 있습니다.
5. 본계약 행 왼쪽 **▶** 버튼을 눌러 변경/추가계약을 펼쳐 봅니다.
6. 특정 행을 클릭하면 해당 발주의 상세/수정 화면으로 이동합니다.

### 주요 버튼/동작

| 버튼 | 동작 | 조건 |
|------|------|------|
| 검색 | 검색 조건으로 목록 조회 | 항상 |
| 엑셀 | 조회 결과를 Excel 파일로 내려받기 | 항상 (다운로드 중 비활성) |
| 등록 | 발주 등록 화면으로 이동 | **쓰기 권한 있을 때만 표시.** 권한이 없으면 버튼에 "권한이 없습니다" 안내 |

### 오류 메시지 & 대응

| 메시지 | 원인 | 대응 |
|--------|------|------|
| 엑셀 다운로드에 실패했습니다. | 서버 응답 오류·네트워크 문제 | 잠시 후 재시도. 반복되면 관리자 문의 |

## 2.2 발주(납품요구) 등록

### 접근 경로
- 발주목록 → 상단 우측 **[등록]** 버튼
- **화면 주소**: `/admin/order/register`

> 📷 [스크린샷: 발주 등록 화면 — 상단 PDF 업로드 영역 + 기본정보 입력 폼 + 품목 표]

### 등록 방법

발주 등록은 **PDF 자동 추출(권장)** 과 **수동 입력** 두 가지가 있습니다.

#### 방법 1 — PDF 자동 추출 (권장)

1. 화면 상단 **PDF 업로드 영역**에 조달청 납품요구서 **PDF 파일**을 끌어다 놓거나 클릭하여 선택합니다.
   - PDF 외 파일은 받지 않습니다. → 안내: *"PDF 파일만 업로드 가능합니다."*
2. 업로드되면 자동으로 데이터 추출이 진행됩니다. → 진행 표시: *"PDF 파일 업로드 및 데이터 추출 중..."*
3. 추출이 끝나면 안내가 표시됩니다. → *"PDF 데이터 추출 완료. 계약 유형을 선택해주세요."*
4. **계약 유형**을 선택합니다.
   - **본계약**(최초) / **변경계약**(기존 계약 내용 변경) / **추가계약**(별도 차수 추가)
5. 추출된 계약 기본정보와 품목 목록을 확인하고 필요 시 수정합니다.
6. **모든 품목의 납품기한**을 입력합니다. (누락 시 저장 불가 → *"모든 품목의 납품기한을 입력해주세요."*)
7. **[저장]** 을 누릅니다. → 성공: *"계약이 성공적으로 등록되었습니다."*

> 같은 납품요구번호(-00)를 다시 업로드하면 신규 등록 대신 **기존 건 업데이트** 경로로 처리됩니다. → *"기존 납품요구가 업데이트되었습니다."* (기존 ID를 찾지 못하면 *"기존 납품요구 ID를 확인할 수 없습니다. 목록에서 직접 수정해 주세요."*)

#### 방법 2 — 수동 입력

1. 기본 정보를 직접 입력합니다(아래 입력 필드 표 참고).
2. 품목 영역에서 **[품목 추가]** 로 행을 추가하고 품목명·규격·수량·단가를 입력합니다.
3. 모든 품목의 납품기한을 입력합니다.
4. **[저장]** 을 누릅니다.

### 입력 필드 설명

| 필드 | 필수 | 설명 |
|------|:----:|------|
| 계약번호 | O | 계약 고유 번호 |
| 계약일자 | O | 계약 체결일 |
| 납품요구번호 | O | 조달청 발행 번호(예: `R26TB0...-00`). 끝 `-00`은 본계약, `-01` 이상은 변경계약 |
| 납품요구일자 | O | 조달청 납품요구일 |
| 사업명 | O | 현장/사업명 |
| 수요기관명 | O | 발주처 기관명 |
| 계약 유형 | O | 본계약 / 변경계약 / 추가계약 |
| 품목별 납품기한 | O | 품목마다 입력(전체 입력해야 저장 가능) |

### 주의사항

> **변경계약·추가계약 등록 시** 반드시 어느 본계약에 연결되는지 확인하세요. 같은 납품요구번호 체계(-00 → -01)로 연결되어 목록 트리에 하위로 표시됩니다. 연결이 끊기면 별도 본계약으로 잘못 등록될 수 있습니다.

### 오류 메시지 & 대응

|--------|------|------|

| 수금 확인 처리 중 오류가 발생했습니다. | 수금 확인 처리 실패 | 잠시 후 재시도, 반복 시 관리자 문의 |

## 3.1 출하 목록 조회

### 접근 경로
- **메뉴**: 출하관리 → 출하목록
- **화면 주소**: `/admin/shipping/list`

> 📷 [스크린샷: 출하 목록 화면 — 검색줄 + 출하 목록 테이블(합지/추가 배지 포함)]

### 화면 구성

출하 목록은 각 출하 건의 상태·수량·금액을 한 줄로 보여줍니다. 일부 행에는 다음 배지가 표시됩니다.
- **합지**: 여러 발주 품목이 한 출하로 합쳐진 건
- **추가**: 추가변경으로 품목/수량이 더해진 건

목록 컬럼(좌→우): **출하NO · 납품요구일자 · 수요기관 · 사업명 · 출하일자 · 상태 · 출고 · 출하수량 · 출하금액 · 비고**

| 상태 | 설명 | 표시 색상 |

| 배송완료 | 현장 도착 | 주황색 |
| 납품확인 | 납품확인 완료 | 녹색 |

### 검색 조건

| 검색 항목 | 입력 방식 | 설명 |

| 검색어 | 텍스트 (`수요기관, 사업명, 출하NO`) | 수요기관·사업명·출하번호 통합 검색 |
| 상태 | 드롭다운 | 등록 / 운송중 / 배송완료 / 납품확인 |

### 단계별 조작 — 조회하기
1. 출하관리 → 출하목록으로 이동합니다.
2. 출하일자 기간·납품요구번호·검색어·상태 중 필요한 조건을 입력합니다.
3. **[검색]** 또는 입력 후 **Enter** 로 조회합니다.
4. 행을 클릭하면 해당 출하의 상세/수정 화면으로 이동합니다.

### 주요 버튼/동작

| 버튼 | 동작 | 조건 |
|------|------|------|

| 등록 | 출하 등록 화면으로 이동 | 쓰기 권한 있을 때만(없으면 "권한이 없습니다") |

| 엑셀 다운로드에 실패했습니다. | 서버/네트워크 오류 | 잠시 후 재시도 |

## 3.2 출하 등록

### 접근 경로
- 출하목록 → 상단 우측 **[등록]** 버튼
- **화면 주소**: `/admin/shipping/register`

> 📷 [스크린샷: 출하 등록 화면 — 발주 선택 + 자동 채움 기본정보 + 품목/수량 입력 표]

### 등록 절차

#### Step 1 — 발주(납품요구) 선택
1. **납품요구번호(발주번호)** 필드의 **[조회]** 로 발주를 검색·선택합니다. (`납품요구번호를 선택하세요`)
2. 발주를 선택하면 **납품요구일자·사업명·수요기관명·담당자·건설사** 등이 **자동으로 채워집니다.** (`발주 선택 시 자동으로 입력됩니다`)
   - 발주 정보를 불러오지 못하면 → *"발주 정보를 불러오는데 실패했습니다."*

#### Step 2 — 출하 품목 및 수량 입력
1. 발주 품목 중 출하할 품목을 추가합니다.
   - 이미 추가한 품목을 또 추가하면 → *"이미 추가된 품목입니다."*
2. 각 품목의 **출하 수량**을 입력합니다.
   - 0 이하 등 잘못된 값 → *"올바른 수량을 입력하세요."*
   - 잔여수량 초과 → *"출하수량은 잔여수량을 초과할 수 없습니다."* (출하수량 ≤ 발주수량 − 기출하수량)

#### Step 3 — 공급원·운송·기타 정보
1. **공급원**(제조사/OEM)을 선택합니다. **(필수)**
2. **출하일자**를 선택합니다. **(필수)**
3. **배송비** 를 입력합니다(기본 0).
4. **운송비 부담** 을 선택합니다. **이 선택에 따라 배송비가 어디에 반영되는지가 달라집니다.** (아래 표 참고)
5. **운송사** 를 선택합니다. 중앙운수 같은 운송사와 OEM 제조사가 함께 목록에 나옵니다. 지정하지 않으려면 **[선택 안 함]** 을 둡니다.
6. 비고 등 부가 정보를 입력합니다.

### 운송비 부담 3가지

운송비는 **누가 내는가**에 따라 세 갈래이고, 갈래마다 반영되는 곳이 다릅니다.

| 선택값 (화면 표기) | 누가 부담 | OEM 월별 원장 | 마진 원가 | 언제 쓰나 |
|--------------------|-----------|---------------|-----------|-----------|
| **OEM 부담 (청구 없음)** | 제조사 | **반영 없음** | 반영 없음 | 일반적인 경우. 이미 SKU 원가에 녹아 있음 |
| **OEM 에 지불 (원장 포함)** | 리드파워 → 제조사에 지급 | **가산** | (원장 경유) | 주문량이 소량이라 운반비를 제조사에 따로 지불할 때 |
| **리드파워 부담 (마진 원가만)** | 리드파워 → 운송사에 직접 지급 | 반영 없음 | **반영** | 창고이동 후 리드파워가 직접 운송할 때 |

선택하면 입력란 아래 안내 문구가 바뀝니다.

| 선택값 | 화면 안내 문구 |
|--------|----------------|
| OEM 부담 | *"OEM 제조회사가 부담합니다. 원장·마진 어디에도 반영되지 않습니다."* |
| OEM 에 지불 | *"소량 주문 등으로 운반비를 OEM 에 지불하는 경우입니다. 출하일이 속한 달의 OEM 원장에 가산됩니다."* |
| 리드파워 부담 | *"창고이동 후 리드파워가 직접 운송하는 경우입니다. 마진 원가에만 반영되고 원장에는 실리지 않습니다."* |

> **기본값은 "OEM 부담" 입니다.** 실제로 제조사에 운반비를 지급하는 건이면 **반드시 "OEM 에 지불" 로 바꿔야** 그 달 원장에 실립니다. 그대로 두면 제조사에 줄 돈이 원장에서 누락됩니다.

> **원장에 실릴 때의 귀속** — 출하 명의가 아니라 **생산자** 기준입니다. 해당 출하에 연결된 발주서의 생산자(없으면 그 발주서 명의)로 잡히고, 연결된 발주서가 없으면 출하의 공급원으로 잡힙니다.

> **배차가 늦어 출하 시점에 운송비를 못 정한다면** 일단 저장하고, 나중에 [3.6 출하 사후 처리](#36-출하-사후-처리)에서 확정하면 됩니다.

#### Step 4 — 저장
1. 입력 내용을 확인합니다.
2. **[저장]** 을 누릅니다.
   - 출하 품목이 없으면 → *"출하할 품목이 없습니다. 출하수량을 입력해주세요."*
   - 성공 → *"출하 정보가 저장되었습니다."*

### 입력 필드 설명

| 필드 | 필수 | 설명 |
|------|:----:|------|
| 납품요구번호(발주번호) | O | 출하할 발주. [조회]로 선택 |
| 납품요구일자 | 자동 | 발주 선택 시 자동 |
| 사업명 | 자동 | 발주 선택 시 자동 |
| 출하일자 | O | 출하 날짜 |
| 상태 | - | 출하 상태(기본 '등록') |
| 공급원 | O | 제조사/OEM 공급처 |
| 수요기관명 | O | 발주처(자동) |
| 기관번호 | - | 수요기관 식별번호 |
| 담당자 / 건설사 / 현장담당자 | 자동/- | 발주 기준 자동 또는 보완 입력 |
| 배송비 | - | 운송 비용(기본 0) |
| 운송비 부담 | - | OEM 부담 / OEM 에 지불 / 리드파워 부담. **기본값 「OEM 부담」** |
| 운송사 | - | 중앙운수 등 운송사 또는 OEM 제조사. 선택 안 해도 됨 |
| 총 출하수량 / 총 금액 | 자동 | 품목 입력에 따라 자동 계산 |

### 오류 메시지 & 대응

| 메시지 | 원인 | 대응 |
|--------|------|------|
| 올바른 수량을 입력하세요. | 수량이 0 이하/형식 오류 | 1 이상 숫자로 입력 |
| 이미 추가된 품목입니다. | 동일 품목 중복 추가 | 기존 행의 수량을 수정 |
| 출하수량은 잔여수량을 초과할 수 없습니다. | 발주 잔여수량 초과 | 잔여수량 이내로 조정 |
| 출하할 품목이 없습니다. 출하수량을 입력해주세요. | 품목/수량 미입력 상태로 저장 | 품목 추가 후 수량 입력 |
| 출하 정보 저장에 실패했습니다. | 검증 실패·서버 오류 | 필수 필드(공급원·출하일자) 확인 후 재시도 |
| 발주 정보를 불러오는데 실패했습니다. | 발주 조회 실패 | 납품요구번호 재선택, 반복 시 관리자 문의 |

### 출하 금액은 어떤 단가로 잡히나

출하 금액은 **그 발주의 계약 단가**(납품요구서에 적힌 단가)로 계산됩니다. 품목에 등록해 둔 기본
판매단가가 아닙니다. 계약 단가를 모두 합하면 발주의 **품대계**가 되므로, 출하 금액·기성 청구액·
매출이 같은 기준으로 맞물립니다.

> 계약에 없는 품목(합지·대체로 새로 담은 SKU)만 예외적으로 품목 기본 단가가 적용됩니다.

## 3.3 출고요청 (운송 등록 전 필수)

출하를 저장했다고 바로 운송장을 끊을 수 있는 게 아닙니다. **출고요청을 거쳐야** 운송 등록 화면에서
그 출하를 고를 수 있습니다. 출고요청은 "이 물량을 실제로 내보내 달라"는 창고·제조사 쪽 지시입니다.

### 접근 경로
- 출하 상세 화면(`/admin/shipping/edit/{출하ID}`) 상단 **[출고요청]** 버튼

> 📷 [스크린샷: 출고요청 모달 — 상단 재고/발주 확인 결과 + 배송지 + 현장 인수자]

### 먼저 갖춰져야 하는 것

버튼이 **[재고부족]** 으로 회색이면 아직 내보낼 물량이 없다는 뜻입니다. 둘 중 하나를 채우세요.

| 경우 | 필요한 것 |
|------|-----------|
| 본사 재고로 내보낼 때 | 공급원을 **리드파워 본사**로 두면 본사 창고 재고로 판정합니다 |
| 제조사가 만들어 보낼 때 | 그 제조사 앞으로 **발주서를 발행하고 [접수]까지** 끝내야 합니다 ([9장 제조생산](#9-제조생산--원가-관리)) |

> **발주서는 「접수(ACCEPTED)」부터 인정됩니다.** 발행만 해두고 접수하지 않으면 계속 [재고부족]으로 보입니다.

### 절차

1. 출하 상세에서 **[출고요청]** 을 누릅니다.
2. 상단에서 품목별 재고·발주 상태를 확인합니다.
   - *"모든 품목의 재고/발주가 확인되었습니다."* → 진행 가능
   - *"다음 품목의 재고가 부족합니다. 발주서를 먼저 발행하세요: ○○"* → 발주서부터 처리
3. **배송지 정보**를 확인합니다(출하에 입력해 둔 주소가 자동으로 들어옵니다). **현장 도착 예정일시**를 지정합니다.
4. **현장소장**을 선택합니다. **(필수)** 선택하면 건설사·인수자명·연락처가 자동으로 채워집니다.
5. **[출고요청]** 을 누릅니다. → *"출고요청이 생성되었습니다."*

> **현장소장은 미리 등록돼 있어야 합니다.** 목록에 없으면 기초정보에서 먼저 등록하세요.
> 이 단계에서는 문자가 나가지 않습니다. 문자는 운송 등록 후 [메시지] 를 누를 때 발송됩니다.

### 다음 단계로 넘어가는 조건

출고요청을 했더라도 **입고가 끝나야** 운송 등록이 열립니다. 제조사 발주 건이라면 발주서에서
**[생산완료 체크] → [생산완료 저장]** 을 해야 입고 수량이 잡힙니다(9장 참조). 그 전에는 운송 등록
화면의 출하 선택 버튼에 *"입고 완료 후 운송 등록이 가능합니다"* 가 뜨며 눌리지 않습니다.

### 오류 메시지 & 대응

| 메시지 | 원인 | 대응 |
|--------|------|------|
| 다음 품목의 재고가 부족합니다. 발주서를 먼저 발행하세요: ○○ | 재고·접수 발주서 모두 없음 | 발주서 발행 후 접수, 또는 본사 재고 확인 |
| 입고 완료 후 운송 등록이 가능합니다 | 출고요청은 했으나 입고 전 | 발주서에서 생산완료 저장 |
| 해당 출하에 이미 출고요청이 존재합니다. | 중복 요청 | 기존 출고요청 상태 확인 |
| 삭제된 출하는 출고요청할 수 없습니다. | 삭제된 출하 | 목록 새로고침 |
| 출고요청이 진행 중인 출하는 OEM 제조사를 변경할 수 없습니다. | 진행 중 제조사 변경 | 출고요청 취소 후 변경 |

## 3.4 운송장 등록 · 납품확인 링크 발송

출고요청과 입고가 끝난 출하에 대해 **운송장을 발급**하고, 현장에 **납품확인 링크를 문자로 보냅니다.**

### 접근 경로
- **메뉴**: 출하관리 → 운송관리 → 상단 **[등록]**
- **화면 주소**: `/admin/transport/register` (목록은 `/admin/transport/list`)

> 📷 [스크린샷: 운송장 등록 화면 — 출하 선택 + 자동 채움 배송지/인수자 + 운송 정보 입력]

### 등록 절차

1. **출하NO** 의 **[조회]** 로 운송 대상 출하를 찾습니다.
   - 목록에는 **아직 운송장이 없는 출하**만 나옵니다.
   - 상태가 **충족** 이면 선택 가능, **입고대기** 면 버튼이 잠깁니다
     (*"입고 완료 후 운송 등록이 가능합니다"*).
2. 출하를 선택하면 **사업명·납품요구번호·수요기관·현장소장·건설사·인수자·연락처·배송지**가 자동으로 채워집니다.
3. **운송 정보**를 입력합니다.

| 필드 | 필수 | 설명 |
|------|:----:|------|
| 기사명 | - | 등록된 기사 목록에서 선택. 없으면 비워 두고 운송사명만 입력 |
| 운송사명 | - | 기사 선택 시 자동. 직접 입력도 가능(예: 중앙운수) |
| 기사 연락처 | **O** | 납품확인 문자가 이 번호로 갑니다 |
| 차량번호 | - | 예: 12가 3456 |
| 배차/출차 시각 · 도착 예정 시각 | - | 기본값이 채워져 있으며 수정 가능 |
| 배송 메모 | - | 현장 전달사항 |

4. **[저장]** → *"운송장이 등록되었습니다. 운송장번호: 20260917-6757-001"*
   - 운송장번호는 **자동 채번**됩니다(`날짜-기사연락처 뒤4자리-일련번호`).

### 납품확인 링크 발송 ⚠ 실제 문자가 나갑니다

1. **운송관리 목록**에서 해당 행의 **[메시지]** 를 누릅니다.
2. 확인 창에서 받는 사람을 반드시 확인합니다.
   *"기사에게 메시지를 전송하시겠습니까? / 기사명 · 연락처 · 운송장번호"*
3. 확인하면 **LMS 2통**이 발송됩니다.

| 받는 사람 | 내용 |
|-----------|------|
| **기사** | 납품확인 요청 + **모바일 납품확인 링크**(24시간 유효) |
| **현장소장** | 배송 출발 알림(출발시간·예상도착·기사 연락처) |

> ⚠ **테스트라도 실제 문자가 발송됩니다.** 번호를 반드시 확인하고 누르세요.
> 발송 이력은 문자관리 메뉴에서 확인할 수 있습니다.

> 링크를 받은 현장에서 진행하는 절차는 [4.3 모바일 납품확인](#43-모바일-납품확인-현장-담당자)을 보세요.
> 이미 완료된 건의 링크를 다시 누르면 *"해당 작업은 이미 완료되었습니다."* 안내가 나옵니다.

## 3.5 출하 수정 및 추가변경

### 접근 경로
- 출하목록에서 해당 행 클릭 → 출하 상세/수정 화면
- **화면 주소**: `/admin/shipping/edit/{출하ID}`

### 일반 수정
출하 등록 후 **납품확인 전**까지 출하일자·공급원·운송/배송 정보·비고 등을 수정할 수 있습니다. **[저장]** 으로 반영합니다.

### 추가변경 (수량 변경)
이미 등록된 출하의 수량을 바꿔야 할 때 사용합니다.

1. 출하 상세 화면에서 **[추가변경]** 을 누릅니다.
2. 변경 유형(수량 증가/감소)과 변경 수량, **변경 사유(필수)** 를 입력합니다.
3. **[변경 적용]** 을 누릅니다.

> **제한**: 해당 출하가 **기성금 청구에 포함된 경우** 수량 변경이 불가합니다. 이때는 새 출하를 등록하세요.

### 변경 이력 조회
출하 상세 화면의 **[변경 이력]** 에서 변경 일시 · 변경 전/후 수량 · 사유 · 변경자를 확인할 수 있습니다.

## 3.6 출하 사후 처리

출하가 끝난 **뒤에야** 확정되는 값들이 있습니다. 그런 건들을 한 곳에서 처리합니다.

### 왜 따로 있나

| 상황 | 왜 출하 때 못 정하나 |
|------|----------------------|
| **운송비** | 중앙운수 등의 배차가 늦어 출하 시점에 금액·부담 주체가 정해지지 않음 |
| **손실** | 현장에 도착한 뒤에야 수량 부족·스펙 오납이 드러남 (영업담당 현장 확인) |
| **가공비** | 제조사와 협의가 끝나야 금액이 확정됨 |

### 화면이 둘로 나뉘어 있습니다

**보는 곳**과 **처리하는 곳**이 다릅니다.

| 화면 | 역할 |
|------|------|
| **출하관리 → 출하 사후 처리** | **목록.** 어디까지 정리됐는지 봅니다. 들어가면 바로 보입니다(검색 안 해도 됨) |
| 그 화면의 **[사후 처리 등록]** 또는 **행 클릭** | **등록.** 실제로 값을 넣습니다 |

### 접근 경로 — 세 가지

| 경로 | 언제 |
|------|------|
| **출하관리 → 출하 사후 처리** → [사후 처리 등록] | 처음부터 찾아 들어갈 때 |
| 같은 목록에서 **행 클릭** | 목록에서 그 건을 찾아 놓았을 때. 바로 선택된 채로 열립니다 |
| **출하 상세**(출하 수정) 화면의 **[사후 처리]** 버튼 | 출하를 보다가 바로 넘어갈 때 |

> **출하관리 목록에는 [처리] 버튼이 없습니다.** 목록은 보는 곳이라, 비고 칸에 **운송비·가공비·손실** 배지로 상태만 보여줍니다. 배지에 마우스를 올리면 금액이 나옵니다.

> 📷 [스크린샷: 출하 사후 처리 목록 — 운송비·가공비·손실 컬럼]

### 목록 화면

| 컬럼 | 내용 |
|------|------|
| 수량 | 출하 수량. 손실이 있으면 아래에 `손실 8 → 유효 906㎡` 병기 |
| 운송비 | 금액과 부담 유형 |
| 가공비 | 연결된 발주서들의 가공비 합계 |
| 손실 | 확정된 손실 수량(㎡) |

**범위**를 「처리 등록분」(기본)과 「전체 출하」 중에 고를 수 있습니다. 기본은 **이미 처리한 건만** 보여줍니다. 아직 처리 안 한 건을 찾으려면 「전체 출하」로 바꾸세요.

### 등록 화면 — 단계별 조작

#### Step 1 — 출하 찾기

다음 조건으로 검색합니다. 여러 개를 함께 넣을 수 있습니다.

| 조건 | 설명 |
|------|------|
| 출하일 | 기간. 기본은 오늘까지 |
| 출하NO | 출하번호 |
| 납품요구번호 | `R25TB...` 형식 |
| 사업명 | 일부만 넣어도 됩니다 |
| 수요기관 | 일부만 넣어도 됩니다 |

목록에서 **행을 클릭**하면 그 출하가 선택됩니다(왼쪽 라디오 표시). 목록이나 출하 상세에서 넘어온 경우에는 **이미 선택된 상태**로 열립니다.

#### Step 2 — 처리 유형 고르기

출하를 고르면 아래에 카드 3개가 열립니다. **각 카드에 현재 상태가 적혀 있어** 눌러보기 전에 무엇이 들어 있는지 알 수 있습니다.

| 카드 | 하는 일 | 어디에 저장되나 | 카드에 표시 |
|------|---------|-----------------|-------------|
| **운송비 확정** | 부담 유형 · 운송사 · 금액 · 원장 반영 월 | 그 **출하** | `현재 150,000원` 또는 `미입력` |
| **손실 등록** | 수량 부족 / 규격 오납 | 새 **손실** 건 | `등록 1건 · 아래에서 선택` 또는 `없음` |
| **가공비 입력** | 연결된 발주서의 가공비 | 그 **발주서** | `현재 300,000원` 또는 `미입력` |

**손실만 다릅니다.** 운송비·가공비는 출하당 1건이라 카드를 누르면 기존 값이 폼에 들어옵니다. 손실은 **품목별로 여러 건**이 생기므로, 이미 등록된 손실이 있으면 **카드 아래에 목록**이 펼쳐집니다.

- 목록의 **행을 누르면 그 손실을 수정**합니다.
- **[손실 등록] 카드**는 언제나 **새 손실**을 만듭니다(다른 품목에서 또 날 수 있으므로).
- 정산이 **차감반영**된 건은 눌러도 막히고 안내가 나옵니다.

> 저장해도 **출하 선택은 유지**됩니다. 운송비 → 가공비 → 손실을 연달아 처리할 수 있습니다.

### 운송비 확정

부담 유형 3가지는 [3.2 운송비 부담 3가지](#운송비-부담-3가지)와 같습니다.

**부담 유형마다 그 돈이 실리는 장부가 다릅니다.**

| 부담 유형 | 누가 내나 | 어느 장부에 실리나 | 운송사 | 원장 반영 월 |
|-----------|-----------|--------------------|--------|--------------|
| **OEM 부담** | 제조사가 자기 돈으로 | 어디에도 안 실림 (이미 SKU 원가에 녹아 있음) | 선택 | 칸이 안 나옴 |
| **OEM 에 지불** | 리드파워 → 제조사 | [8.6 월별 매출원장](#86-oem-지급-관리-월별-매출원장)에 **가산** | 선택 | 나옴 |
| **리드파워 부담** | 리드파워 → 운송사 | [3.7 운송비 원장](#37-운송비-원장)에 잡힘 | **필수** | 나옴 |

- **「리드파워 부담」은 운송사를 반드시 골라야 합니다.** 운송사가 곧 운송비 원장의 집계 기준이라, 비워 두면 그 달 원장에서 갈 곳을 잃습니다. 화면이 **중앙운수를 기본으로 채워** 주고, 비운 채 저장하면 막힙니다.
- **「원장 반영 월」은 「OEM 에 지불」과 「리드파워 부담」 둘 다** 나타납니다. **비워 두면 출하일이 속한 달로 자동 지정**됩니다 — 출하일이 이미 있으니 같은 달을 또 고를 필요가 없습니다.
  - 「OEM 에 지불」: **그 달 지급이 이미 끝났다면 다음 달을 직접 지정**하세요.
  - 「리드파워 부담」: **출하는 지난달인데 운송비를 이번 달에 정산**한다면 이번 달을 지정하세요.
- 「OEM 부담」인데 금액을 넣으면 *"제조사가 자기 돈으로 내는 것이라 원장·마진 어디에도 반영되지 않습니다"* 라는 안내가 나옵니다.

> **기준 월은 출하일이 아니라 「원장 반영 월」입니다.** 원장은 이 값으로 모읍니다. 출하일과 정산월이 어긋나는 건을 위해 직접 고를 수 있게 되어 있습니다.

### 손실 등록

[9.4 손실 관리](#94-손실-관리)와 같은 입력 창이 열립니다. 이미 출하가 정해져 있으므로 출하를 다시 고르지 않아도 됩니다.

### 가공비 입력

선택한 출하에 **연결된 발주서 목록**이 나옵니다. 그중 하나를 골라 가공비를 입력합니다.

> **발주서와 출하는 1:1 이 아닙니다.** 한 출하에 여러 발주서가 물릴 수 있어 목록으로 보여줍니다. 발주서를 고르면 그 발주서에 이미 저장된 가공비가 입력란에 채워집니다.

> **임시저장(DRAFT) 발주서의 가공비는 원장에 실리지 않습니다.** 그런 발주서를 고르면 경고가 나옵니다. **발행해야** 그 달 원장에 나타납니다.

> **연결된 발주서가 없을 수 있습니다.** 재고에서 바로 나간 출하가 그렇습니다. 이때는 가공비를 넣을 대상이 없습니다.

### 오류 메시지 & 대응

| 메시지 | 원인 | 대응 |
|--------|------|------|
| *"조건을 넣고 검색하세요."* | 아직 검색 전 | 조건을 넣고 **[검색]** |
| *"검색 결과가 없습니다."* | 조건에 맞는 출하 없음 | 기간을 넓히거나 조건을 줄여 보세요 |
| *"이 출하에 연결된 발주서가 없습니다."* | 재고 출고분 등 | 가공비 대상이 아닙니다 |
| *"먼저 위에서 출하를 선택하세요."* | 출하 미선택 | 목록에서 행을 클릭 |
| *"리드파워 부담 운송비는 운송사를 지정해야 합니다."* | 「리드파워 부담」인데 운송사가 비어 있음 | 운송사를 고르세요(대개 **중앙운수**). 이 값이 운송비 원장의 집계 기준입니다 |
| *"출하일이 없어 원장 반영 월을 정할 수 없습니다."* | 출하일도 없고 반영 월도 안 넣음 | 「원장 반영 월」을 직접 지정하세요 |

## 3.7 운송비 원장

**리드파워가 부담한 운송비**를 운송사별·월별로 모아 봅니다. 운송사에 줄 돈을 정산할 때 쓰는 근거 자료입니다.

**출하관리 → 운송비 원장**

### 무엇이 실리나

**「리드파워 부담」으로 확정한 운송비만** 실립니다.

| 부담 유형 | 이 원장에 | 이유 |
|-----------|-----------|------|
| **리드파워 부담** | ✅ 실림 | 리드파워가 운송사에 낼 돈 |
| OEM 에 지불 | ❌ 안 실림 | 제조사에게 줄 돈이라 [8.6 월별 매출원장](#86-oem-지급-관리-월별-매출원장)에 이미 가산됨 |
| OEM 부담 | ❌ 안 실림 | 제조사가 자기 돈으로 낸 것이라 리드파워 장부와 무관 |

> **같은 돈이 두 장부에 잡히지 않습니다.** 「OEM 에 지불」을 여기 함께 담으면 제조사 지급액과 운송사 정산액에 같은 금액이 두 번 계상됩니다.

### 화면 보기

| 영역 | 내용 |
|------|------|
| **조회 월** | 기준은 출하일이 아니라 **원장 반영 월**입니다 |
| **운송사** | 「전체」 또는 특정 운송사. 실적이 없는 운송사도 목록에는 나옵니다 |
| **요약 카드** | 출하 건수 · 운송비 합계(공급가액) · 부가세 10%(참고) · 합계+부가세(참고) |
| **운송사 칩** | 「전체」로 볼 때, 운송사별 건수·합계를 한 줄로. **누르면 그 운송사만** 좁혀 봅니다 |
| **내역** | 출하일 · 출하번호 · 납품요구번호 · 수요기관 · 배송지 · 수령인 · 제조사 · 운송비 |

> **부가세는 참고값입니다.** 실제 청구는 운송사가 끊는 세금계산서를 따릅니다. 화면에서도 흐린 글씨로 「(참고)」라고 표시됩니다.

> 내역의 **제조사**는 "누가 만든 물건을 실었는지"를 보는 참고 정보입니다. 운송사 청구액과는 관계가 없습니다.

### 엑셀 내려받기

우측 상단 **[엑셀 내려받기]** 로 그 달 내역과 합계를 한 장에 받습니다. 운송사에 보내는 정산 근거로 씁니다. 운송사를 골라 둔 상태면 그 운송사만 받습니다.

### 원장에 안 보일 때

| 증상 | 확인할 것 |
|------|-----------|
| 확정했는데 목록에 없음 | 부담 유형이 **「리드파워 부담」**인지. 다른 유형은 이 원장 대상이 아닙니다 |
| 다른 달에 있음 | **원장 반영 월**을 확인하세요. 출하일이 아니라 이 값으로 모읍니다 |
| 운송사가 「미지정」 | 예전에 운송사 없이 저장된 건입니다. 사후 처리에서 운송사를 지정하면 잡힙니다 |

> 이 화면은 **관리자 전용**입니다. 제조사 계정에는 메뉴가 보이지 않습니다 — 리드파워가 운송사에 내는 돈이라 제조사와 무관하고, 열면 거래처 운송 단가가 드러납니다.

# 4. 납품 확인

## 4.1 납품확인 개요

납품확인은 현장에서 실제 물품을 수령하고 확인하는 과정입니다. 현장 담당자(인수자)가 **모바일 기기**로 직접 처리합니다.

### 납품확인 프로세스

```
출하 (배송완료 상태)
       ↓  관리자: 모바일 URL 발송 (SMS/LMS)
현장 담당자 URL 접속 (로그인 불필요, 토큰 인증)
       ↓
정보·수량 확인 → (사진 촬영) → 터치 서명 저장
       ↓
납품확인 완료
```

> **두 가지 진행 모드가 있습니다.**
> - **일반(full) 모드**: 현장 담당자가 **사진 업로드 + 서명**을 모두 진행
> - **서명전용(signature) 모드**(URL `?mode=signature`): 사진은 **관리자가 미리 업로드**하고, 현장 담당자는 **서명만** 진행
>
> 화면에 *"납품 사진은 관리자가 처리했습니다. 서명만 진행해주세요."* 가 보이면 서명전용 모드입니다.

## 4.2 관리자 화면 (PC)

### 접근 경로
- **메뉴**: 납품관리 → 납품확인
- **화면 주소**: `/admin/delivery/list`

> 📷 [스크린샷: 납품확인 목록(PC) — 발주 단위 트리 + 출하별 납품확인 상태]

### 화면 구성
납품확인 목록은 **트리 구조**입니다. 발주 단위로 그룹화되고, 각 발주 하위에 출하 건과 납품확인 상태가 표시됩니다.

### 단계별 조작 — 납품확인 URL 발송
1. 납품확인이 필요한 출하 건을 선택합니다.
2. **[납품확인 URL 발송]** 을 누릅니다.
3. **수신자명**과 **휴대폰 번호**를 입력합니다.
4. 메시지 유형(**SMS / LMS**)을 선택합니다.
5. **[발송]** 을 누릅니다.

### URL 유효기간
- 발송된 URL은 **24시간** 동안 유효합니다.
- 만료된 링크로 접속하면 *"서명 링크가 만료되었습니다. 관리자에게 새 서명 링크를 요청해주세요."* 가 표시됩니다. → 관리자가 **재발송**합니다.

## 4.3 모바일 납품확인 (현장 담당자)

### 접속 방법
- 문자로 받은 URL을 터치하면 모바일 브라우저에서 납품확인 페이지가 열립니다.
- **별도 로그인 불필요**(토큰 기반 인증).
- **화면 주소**: `/m/delivery/{토큰}` (서명전용은 `?mode=signature`)

> 📷 [스크린샷: 모바일 납품확인 화면 — 배송정보 + 품목표 + 사진/서명 영역]

### 납품확인 절차

#### Step 1 — 정보 확인
화면 상단에서 **운송장번호 · 차량번호 · 배송지 · 배송예정일 · 현장소장**과 품목 표(품목·규격·수량·비고)를 확인합니다.

> 처음 열면 **납품 확인 절차 안내**(4단계) 팝업이 먼저 뜹니다. [다음]으로 넘기거나 닫고 진행하면 됩니다.
> "다시 보지 않기"를 체크하면 이후 생략됩니다.

#### Step 2 — 사진 (일반 모드)
1. **추가 사진 업로드** 영역에서 사진을 촬영/선택합니다. **(최소 1장, 최대 5장)**
2. 첨부된 사진은 탭하여 크게 볼 수 있고, 잘못 올린 사진은 삭제할 수 있습니다.
   - 삭제 시 확인: *"이 사진을 삭제하시겠습니까?"* / 실패 시 *"삭제 실패: …"*
- 서명전용 모드에서는 이 영역 대신 *"첨부된 사진이 없습니다. 관리자가 이후 업로드할 예정입니다."* 가 표시될 수 있습니다.

#### Step 3 — 서명
1. **현장소장 서명** 영역에 손가락으로 서명합니다.
2. **[서명 저장]** 을 누릅니다. → *"서명이 저장되었습니다."*
3. 서명 저장 시 **GPS 위치**가 함께 기록됩니다. (위치 권한이 없거나 실패해도 서명은 정상 저장됩니다 — 위치는 선택사항)

#### Step 4 — 납품 확인 완료
1. 맨 아래 **[납품 확인 완료]** 를 누릅니다.
2. 확인 창에서 서명·사진 상태를 보고 진행합니다.
   *"납품을 확인하시겠습니까? / 서명: 완료 / 사진: ○장 / 제출 후에는 수정할 수 없습니다."*
3. 완료되면 **인수증 PDF가 자동 생성**되고, 관리자 화면의 납품확인·납품완료 집계에 즉시 반영됩니다.

> **제출하면 되돌릴 수 없습니다.** 사진이나 서명을 잘못 올렸다면 완료 전에 고쳐야 합니다.
> 이미 완료한 뒤 같은 링크를 다시 열면 **"해당 작업은 이미 완료되었습니다."** 안내가 나옵니다(정상).

### 오류 메시지 & 대응

| 메시지 | 원인 | 대응 |
|--------|------|------|
| 서명 링크가 만료되었습니다. | URL 24시간 경과 | 관리자에게 재발송 요청 |
| 최소 1장의 사진을 업로드해주세요. | 사진 없이 완료 시도 | 현장 사진을 1장 이상 첨부 |
| 해당 작업은 이미 완료되었습니다. | 완료된 링크 재접속 | 정상. 추가 작업 불필요 |
| 서명 저장에 실패했습니다. | 네트워크/서버 오류 | 통신 확인 후 재시도 |
| 삭제 실패: … | 사진 삭제 처리 오류 | 잠시 후 재시도 |

# 5. 납품완료계

## 5.1 납품완료계 개요
납품완료계는 모든 납품이 완료된 후 **조달청에 제출하는 공식 문서**입니다. 현장소장·감리원 서명을 받아 완성합니다.

### 납품완료계 상태 흐름
```
PENDING (대기)
   ↓ 첫 출하 생성
IN_PROGRESS (납품중)
   ↓ 모든 납품확인 완료
PENDING_SIGNATURE (서명 대기)
   ↓ 현장소장 서명
PARTIAL_SIGNED (일부 서명)
   ↓ 감리원 서명
COMPLETED (완료) → 3종 PDF 자동 생성
   ↓ 조달청 제출
SUBMITTED (제출완료)
```

## 5.2 납품완료계 목록
### 접근 경로
- **메뉴**: 납품관리 → 납품완료계
- **화면 주소**: `/admin/delivery-done/list`

목록 컬럼: 납품요구번호 · 현장명 · 상태 · 납품확인 현황(예: 5/5) · 서명 현황(현장소장/감리원) · 등록일

## 5.3 납품완료계 상세 화면
### 접근 경로
- 목록에서 행 클릭 → **화면 주소**: `/admin/delivery-done/detail/{ID}`

> 📷 [스크린샷: 납품완료계 상세 — 금액 요약 + 품목 표 + 사진 관리 + 변경 이력]

### 화면 구성
- **금액 요약**: **품목총액**(품대계 = 매출 기준 금액) + **수수료**(참고 표기)
- **품목 표** 컬럼: 순번 · 품명 · 규격 · 단위 · 단가 · 발주수량 · 추가수량 · 유효수량 · 납품수량 · 잔여수량 · 완료. 추가분 품목에는 **추가** 배지가 붙습니다.
- **변경 이력**: 일시 · 유형 · 품목 · 증감 기록

### 사진 관리 (사진대지용)
납품완료계 상세에서 현장 사진을 관리하고, **사진대지 PDF에 들어갈 사진**을 지정합니다.

| 동작 | 설명 | 안내/제약 |
|------|------|-----------|
| 사진 교체 | 기존 사진을 다른 사진으로 교체 | 성공: "사진이 교체되었습니다." |
| 사진 추가 | 사진을 추가 업로드 | "사진이 추가되었습니다. 사진대지에 포함하려면 '사진 선택'에서 지정하세요." |
| 사진대지 선택 | 사진대지에 넣을 사진 지정 | **출하당 최대 2장**, **최소 1장**. 저장 성공: "사진대지 선택이 저장되었습니다." |

- 최대 초과: *"사진대지는 출하당 최대 2장까지입니다. 다른 사진의 '대지'를 먼저 해제한 후 선택해 주세요."*
- 최소 미달: *"출하당 최소 1장을 선택해야 합니다."*
- 사진을 교체/추가/재선택하면 **사진대지 PDF가 자동으로 다시 생성**됩니다.

### 재계산 (관리자 전용)
출하 이관 등으로 수량/금액이 어긋났을 때, 상세 화면의 **[재계산]** 버튼(SYSTEM_ADMIN 권한)으로 납품완료 수량·금액을 다시 맞춥니다. 확인 창 후 실행되며, 성공 시 *"재계산이 완료되었습니다."*, 실패 시 *"재계산에 실패했습니다."* 가 표시됩니다.

## 5.4 서명 수집
### 단계별 조작
1. 납품완료계 상세에서 **[서명 URL 발송]** 을 누릅니다.
2. 서명자를 선택합니다. **현장소장 → 감리원 순서**입니다.
3. 메시지 미리보기(납품요구번호·수요기관·사업명·서명 URL)를 확인하고 **[발송]** 합니다.
4. 서명 현황은 **대기(⏳) / 완료(✅)** 로 표시됩니다. URL 유효기간은 **24시간**입니다.

## 5.5 PDF 문서 생성 및 다운로드
**현장소장 + 감리원** 양측 서명이 완료되면 3종 PDF가 자동 생성됩니다.

| 문서 | 설명 |
|------|------|
| 납품확인서 | 품목별 납품 내역 확인 문서 |
| 납품완료계 | 최종 납품완료 보고서(조달청 제출용) |
| 사진대지 | 사진대지로 지정한 현장 사진 모음(출하당 1~2장) |

다운로드: 상세 화면의 **문서** 영역에서 문서별 **[다운로드]**, 또는 **[전체 다운로드]**(ZIP).

## 5.6 조달청 제출
1. 모든 서명 완료와 PDF 생성을 확인합니다.
2. **[제출 완료 처리]** 를 누르면 상태가 **SUBMITTED(제출완료)** 로 바뀝니다.

> **주의**: 제출 완료 처리 후에는 수정이 불가능합니다.

# 6. 자금 관리 - 선급금

> 이 장은 **선급금**(계약 체결 후 납품 전에 선지급받는 금액)의 신청·문서 다운로드·수금 확인 절차를 다룹니다.
> 독자: 회계·자금 담당 실무자. 화면 조작 중심으로 설명합니다.

## 6.1 선급금 개요

선급금은 계약 체결 후 납품 전에 **선지급**되는 금액입니다. 통상 계약금액(품대계)의 **70%**를 선급금으로 지급받습니다.

- **기본 비율**: 70% (신청 모달에서 0~100% 범위로 수정 가능)
- **신청 횟수**: 발주(자금) 1건당 **1회만** 신청 (수금확인 전이면 삭제 후 재신청 가능)
- **금액 기준**: 계약총액 = `orders.item_total_amount`(품대계). 매출·집계와 동일 기준.
- **선급금은 서명 절차가 없습니다.** 신청 즉시 5종 PDF가 자동 생성됩니다.

### 선급금 계산식

```
선급금 예상액 = 계약총액(품대계) × 선급금 비율(기본 70%)
```

예: 계약총액 1억 원 → 70% → 선급금 예상액 **7,000만 원**

> 코드 근거: `AdvancePaymentModal.vue` `expectedAdvanceAmount = Math.round(totalContractAmount × rate/100)`,
> `[id].vue` `expectedAdvanceAmount = Math.floor(contractTotalAmount × rate /100)` (탭 표시는 내림 처리).

### 선급금 프로세스

```
선급금 신청 (비율·금액 입력)
    ↓
5종 PDF 문서 자동 생성
    ↓
상태: REQUESTED (신청)
    ↓
실제 입금 → 입금(수금) 확인 처리
    ↓
상태: PAID (수금완료)
```

> ※ 화면상 선급금에는 별도의 "승인" 버튼이 없습니다. 신청(REQUESTED) 또는 승인(APPROVED) 상태에서 **[입금 확인하기]** 버튼으로 바로 수금 처리합니다. (APPROVED 상태는 백엔드 데이터로는 존재하나, 화면에서 승인 버튼을 통한 별도 단계는 노출되지 않습니다.)

### 선급금 상태값

| 상태 코드 | 화면 라벨 | 의미 |
|-----------|-----------|------|
| REQUESTED | 신청 | 선급금 신청 완료, 입금 대기 |
| APPROVED | 승인 | 승인된 상태 (입금 확인 가능) |
| PAID | 수금완료 | 실제 입금 확인 처리됨 |
| REJECTED | 반려 | 반려된 상태 |

> 코드 근거: `types/fund.ts` `ADVANCE_STATUS_LABELS`.

## 6.2 자금 상세 화면 접근

### 접근 경로

- **메뉴**: 좌측 메뉴 **기성청구** → 목록에서 해당 납품요구 건 행 클릭
- **목록 라우트**: `/admin/funds`
- **상세 라우트**: `/admin/funds/{fundId}`

> 참고: 메뉴/목록 화면의 제목은 **"기성청구"** 이며 (`pages/admin/funds/index.vue` PageHeader title="기성청구"), 화면 설명은 "납품요구별 기성 현황(선급금/기성금/잔금)을 조회하고 관리합니다." 입니다. 선급금·잔금·OEM 지급도 모두 이 화면의 상세 탭에서 처리합니다.

> 📷 [스크린샷: 기성청구 목록 화면 — 요약 카드(총 계약금액/수금 누계/미수금/OEM 지급액) + 검색조건 + 자금 목록 테이블]

### 자금 목록 화면 구성

상단 요약 카드 4개와 검색조건, 목록 테이블로 구성됩니다.

| 요약 카드 | 의미 |
|-----------|------|
| 총 계약금액 | 검색 범위 내 계약총액(품대계) 합계 |
| 수금 누계 | 선급금+기성금+잔금 실수금 합계 |
| 미수금 | 미수금 합계 |
| OEM 지급액 | OEM(제조사) 지급 누계 |

검색 조건: 조회기간(기본 과거 1년~오늘), 납품요구번호, 사업명, 상태(전체/진행중/완료/취소). 상태를 바꾸면 자동 검색됩니다. 우측 상단 **[엑셀]** 버튼으로 현재 검색조건 기준 전체 목록을 `기성청구목록_YYYY-MM-DD.xlsx` 로 내려받습니다.

목록 테이블 열: No, 납품요구번호, 사업명, 선급금, 기성금 누계, 잔금, 수금률, 납품율, 수금구성(선급금/기성금/잔금 배지), 자금상태. 행을 클릭하면 상세 화면으로 이동합니다.

### 자금 상세 화면 구성

> 📷 [스크린샷: 자금 상세 화면 — 기본 정보 카드 + 자금 현황 요약 카드 + 수금 진행률 바 + 4개 탭]

상단에 기본 정보 카드(납품요구번호/현장명/수요기관/상태), 자금 현황 요약 카드(계약총액·선급금·기성금 누계·선급금 차감·잔금·다량납품할인), 수금 진행률 바가 표시됩니다.

그 아래에 **4개의 탭**이 있습니다:

1. **선급금** 탭 (기본 선택)
2. **기성금** 탭
3. **잔금** 탭
4. **OEM 지급** 탭

> 코드 근거: `[id].vue` `tabs = [advance, progress, balance, oem]`, 기본 `activeTab='advance'`.

## 6.3 선급금 신청

### 접근 위치

자금 상세 화면 → **선급금** 탭 → 우측 상단 **[선급금 신청하기]** 버튼

### 단계별 조작

1. 자금 상세 화면에서 **선급금** 탭 선택 (기본 선택됨)
2. 우측 상단 **[선급금 신청하기]** 버튼 클릭
   - 이미 신청한 경우 버튼은 **[선급금 신청완료]** 로 바뀌고 비활성화됩니다.
   - 신청 조건을 충족하지 못하면 버튼이 비활성화되며, 마우스를 올리면 사유가 툴팁으로 표시됩니다.
3. **선급금 신청** 모달 창이 열립니다.
4. 상단 요약에서 **총 계약금액**(수정 불가)·**선급금 비율**(수정 가능)을 확인하면, **선급금 예상액**이 자동 계산됩니다.
5. **선급금 비율**을 조정하면 **신청 금액**이 예상액으로 자동 채워집니다. (필요 시 신청 금액 직접 수정 가능)
6. **신청일**을 선택합니다. (기본값: 오늘)
7. (선택) **비고**를 입력합니다.
8. 하단 **[선급금 신청]** 버튼 클릭
9. "선급금 신청이 완료되었습니다." 결과 모달이 표시되고, 서버가 **5종 PDF**를 자동 생성합니다.
10. 상태: **REQUESTED (신청)**

> 📷 [스크린샷: 선급금 신청 모달 — 총 계약금액/선급금 비율(입력)/선급금 예상액 + 신청 금액·신청일·비고 폼]

### 입력 필드

| 필드 | 의미 | 필수 | 제약 | 비고 |
|------|------|:---:|------|------|
| 총 계약금액 | 계약총액(품대계), 자동 표시 | - | 수정 불가 | 상세 화면 `contractTotalAmount` |
| 선급금 비율 | 선급금 적용 비율(%) | - | 0~100, 정수(step 1) | 기본 70. 변경 시 신청 금액 자동 갱신 |
| 선급금 예상액 | 계약금액 × 비율(자동) | - | 자동 계산 | `Math.round(계약금액 × 비율/100)` |
| 신청 금액 | 실제 신청 금액 | 필수 | 0보다 커야 함, 숫자만 입력 | 천 단위 콤마 자동 표기 |
| 신청일 | 신청 날짜 | 필수 | date 선택 | 기본값 오늘 |
| 비고 | 추가 메모 | 선택 | - | textarea |

### 버튼/동작

| 버튼 | 동작 | 조건 |
|------|------|------|
| [선급금 신청하기] | 신청 모달 열기 | 미신청 + 신청 가능 조건 충족 시에만 활성 |
| [선급금 신청완료] (비활성) | - | 이미 1회 신청한 경우 |
| [선급금 신청] (모달) | 신청 + 5종 PDF 자동 생성 | 신청 금액 > 0, 신청일 입력 |
| [취소] (모달) | 모달 닫기 | 항상 |

### 자동 생성 5종 PDF

# 7. 자금 관리 - 기성금

> 이 장은 **기성금**(납품 진행에 따라 단계별로 청구하는 금액)의 청구·문서 발행·수금 확인 절차를 다룹니다.

## 7.1 기성금 개요

기성금은 납품이 진행됨에 따라 **차수별(1차, 2차, 3차…)로 청구**하는 금액입니다. **납품확인(인수증 서명)이 완료된 출하**를 선택하여 기성금을 청구합니다.

- **청구 단위**: 차수(Baseline). 발주 1건에 여러 차수.
- **청구 대상**: 납품확인 완료된 출하 중 아직 기성 청구에 포함되지 않은 출하.
- **금액 산정**: 선택한 출하의 금액을 합산하되, **전량 출하된 품목은 원수량(order_items)으로 정합(cap)** 하여 저장값과 일치시킵니다(미리보기에 자동 반영). 따라서 "출하금액 단순합"과 "실제 청구금액"이 다를 수 있습니다.
- **다량납품할인**: 단가합(룰 기준) ≥ 1억 2%, ≥ 2억 3%(조달청 원단위 절사). 표준 발주에만 자동 적용.
- **OEM 지급 예정액**: 청구금액 × 선급금 비율(기본 70%).

### 기성금 계산식

```
선택 출하 합계 = Σ(선택한 출하의 totalAmount)
청구금액(저장값) = 원수량 정합(cap) 적용 합계   ← 미리보기 = 백엔드 저장값
다량납품할인액 = 청구금액 − (청구금액 × (1−할인율)) 의 원단위 절사
할인 후 청구액 = 청구금액 − 다량납품할인액
선급금 차감액 = MIN(할인 후 청구액 × 선급금율, 미정산 선급금 잔액)
실수금액 = 할인 후 청구액 − 선급금 차감액
OEM 지급 예정액 = 청구금액 × 선급금율(기본 70%)
```

> 금액 정책: 매출·집계 기준은 품대계(`item_total_amount`)이며, 기성 차수 청구는 별도 회계 규칙(원수량 정합 cap + 다량납품할인)이 적용됩니다.
> 코드 근거: `ProgressPaymentModal.vue` (claimAmount/reconcileDiff/bulkDiscount*/advanceDeductionAmount/actualReceivableAmount/oemPaymentAmount), `baseline.service.ts previewBaseline`.

### 기성금 프로세스 (현재 구현: 서명 없이 즉시 발행)

```
납품확인(인수증 서명) 완료된 출하 선택
         ↓
기성 청구 (차수 생성)
         ↓
서명란 공란 납품확인서 + 사진대지 PDF 즉시 발행
         ↓
(현장 서명을 종이로 받은 경우) 서명본 스캔 PDF 업로드 → 다운로드 시 스캔본 우선
         ↓
실제 입금 후 수금 확인
         ↓
상태: PAID
```

> ⚠️ **중요(코드 vs 지식베이스 불일치)**: 현재 화면 구현은 **서명 절차 없이** 기성 청구 즉시 서명란 공란 납품확인서 PDF를 발행하고, 종이로 받은 서명본을 스캔 업로드하는 방식입니다(`ProgressPaymentModal.submitClaim → baselineService.createBaselineDirect`, 안내: "기성 청구가 완료되었습니다. 납품확인서 PDF를 다운로드할 수 있습니다."). 지식베이스(`domain-rules.yaml progress_payment.requires_signature: true`)와 과거 매뉴얼의 "서명 URL 발송 → 현장소장→감리원 서명" 흐름은 **모바일 서명 발송 방식(레거시/대체 경로)** 으로, 코드상 `ProgressSignatureModal`·`createAndSendSignature`·`sendSignatureUrl` 형태로 남아 있습니다. 7.3에 두 흐름을 모두 정리합니다. 운영에서 실제 사용 중인 경로는 `(확인 필요)`.

## 7.2 기성금 청구

### 접근 위치

자금 상세 화면 → **기성금** 탭 → 우측 상단 **[기성 청구하기]** 버튼

### 청구 조건

- **납품확인(인수증 서명)이 완료된 출하**만 청구 가능
- 이미 기성 청구에 포함된 출하는 목록에 나타나지 않음(선택 불가)
- 납품완료(COMPLETED)된 발주는 기성 청구 불가
- 마지막 1건은 납품완료계용으로 남겨야 할 수 있음(아래 선택 제한 참조)

> 코드 근거: `[id].vue canRequestProgress / getProgressButtonTooltip`, `baseline.service.ts getAvailableShipments`.

### 단계별 조작

#### Step 1. 기성 청구 시작

1. 자금 상세 화면 → **기성금** 탭
2. 우측 상단 **[기성 청구하기]** 버튼 클릭
   - 비활성 시 툴팁으로 사유 표시(아래 표 참조)

#### Step 2. 청구 가능 출하 선택

> 📷 [스크린샷: 기성 청구 모달 — 청구 가능 출하 목록(체크박스) + 청구 금액 계산 섹션 + 품목별 정합 미리보기]

1. **청구 가능 출하 목록**이 표시됩니다(기본적으로 선택 가능 출하가 자동 선택됨).
2. 청구할 출하를 체크박스로 선택/해제합니다(행 클릭으로도 토글). 헤더 체크박스로 전체 선택/해제.
3. 선택 제한이 있는 경우 상단에 경고가 표시됩니다:
   > "마지막 출하는 납품완료계로 처리해야 합니다. 최대 N건까지 선택 가능합니다."
4. 선택에 따라 우측/하단 계산이 실시간 갱신됩니다:
   - **선택한 출하 수 / 선택 출하 합계**
   - **(-) 원수량 정합 (전량 출하분)** 또는 (+) 정합
   - **청구 금액** (원수량 정합 적용된 저장 예정값)
   - **품목별 금회 청구(원수량 정합)** 표: 품목 / 금회수량 / 잔여수량 / 금액
   - **다량납품할인(자동)** 미리보기: 단가합·적용율·할인 전 청구·(-)할인·(=)할인 후 청구액
   - **선급금 차감 계산**(선급금 신청한 경우): 비율·미정산 잔액·(-)차감액·(=)실수금액
   - **OEM 지급 예정 금액**
5. (선택) **비고** 입력

#### Step 3. 청구 확정 (서명 없이 즉시 발행)

1. 하단 **[기성 청구]** 버튼 클릭
2. 차수가 생성되고 **서명란 공란 납품확인서 + 사진대지 PDF**가 즉시 발행됩니다.
3. 알림: "기성 청구가 완료되었습니다. 납품확인서 PDF를 다운로드할 수 있습니다."
4. 기성금 탭 목록에 새 차수가 추가됩니다.

> 코드 근거: `ProgressPaymentModal.vue submitClaim`, `baseline.service.ts createBaselineDirect (createWithoutSignature)`.

### 입력 필드 (기성 청구 모달)

| 필드 | 의미 | 필수 | 제약 | 비고 |
|------|------|:---:|------|------|
| 출하 선택(체크박스) | 청구할 출하 | 필수 | 최소 1건, 선택 제한 시 최대 N건 | 미선택 시 청구 불가 |
| 비고 | 청구 관련 메모 | 선택 | - | - |

| (자동) 다량납품할인 | 단가합 기준 0/2/3% | - | 표준 발주만 | 원단위 절사 |
| (자동) 선급금 차감액 | MIN(할인후청구×율, 미정산잔액) | - | 선급금 신청 시 | - |

|------|------|------|
| [기성 청구하기] | 청구 모달 열기 | 청구 가능 조건 충족 시 활성 |
| 헤더 체크박스 | 전체 선택/해제 | 선택 제한 시 최대 수까지만 |
| [기성 청구] | 차수 생성 + 공란 납품확인서·사진대지 PDF 발행 | 출하 1건 이상 선택 |
| [취소] | 모달 닫기 | 항상 |

### 사용 예시

> 발주 계약총액 1억 원, 선급금 70%(7,000만 원) 신청·수금 완료. 1차로 납품확인 완료된 출하 2건(합계 4,000만 원) 선택.
> - 전량 출하 품목 없음 → 청구금액 4,000만 원
> - 다량납품할인: 단가합 1억 미만이면 미적용(0%) / 1억 이상이면 2% 등 자동
> - 선급금 차감액 = MIN(4,000만×70%=2,800만, 미정산 잔액 7,000만) = 2,800만 원
> - 실수금액 = 4,000만 − 2,800만 = **1,200만 원**
> - OEM 지급 예정액 = 4,000만 × 70% = 2,800만 원

## 7.3 서명 흐름

기성 차수의 납품확인서 서명에는 두 가지 경로가 코드에 존재합니다.

### (A) 현재 화면 기본 경로 — 서명 없이 즉시 발행 + 스캔 업로드

- 기성 청구 시 서명란이 **공란**인 납품확인서 PDF를 즉시 발행.
- 현장에서 종이로 서명을 받은 뒤, 기성금 탭의 **[스캔업로드]** 버튼으로 서명본 스캔 PDF(.pdf, 최대 20MB)를 업로드.
- 이후 다운로드 시 **스캔본이 우선** 제공됩니다.

> 코드 근거: `FundProgressTab.vue` (납품확인서/사진대지/스캔업로드 버튼), `baseline.service.ts uploadConfirmationScan`.

### (B) 레거시/대체 경로 — 모바일 서명 URL 발송

> ⚠️ 아래는 코드에 존재하는 모바일 서명 방식입니다. 현재 운영 사용 여부는 `(확인 필요)`.

- 기성 청구 시 현장소장·감리원에게 서명 URL이 포함된 메시지(LMS/SMS) 발송.
- **서명 순서**: ① 현장소장 → ② 감리원.
- 양측 서명 완료 시 납품확인서·사진대지 PDF 자동 생성.

#### 서명 상태값

| 상태 코드 | 화면 라벨 | 의미 |
|-----------|-----------|------|
| PENDING_SIGNATURE | 서명대기 | 발송 후 서명 대기 |
| PARTIAL_SIGNED | 일부서명 | 현장소장 또는 감리원 중 1명 서명 |
| SIGNATURE_COMPLETED | 서명완료 | 양측 모두 서명 완료 |

서명 URL 유효시간: 24시간(만료 시 재발송 필요). 만료/중복 서명 시 모바일에서 "서명 링크가 만료되었습니다." / "이미 서명이 완료되었습니다." 등의 메시지가 표시됩니다.

> 코드 근거: `types/baseline.ts SIGNATURE_STATUS_LABELS`, `baseline.service.ts sendSignatureUrl / baselineMobileService.uploadSignature`, `domain-rules.yaml signature_rules.baseline_signature (url_validity_hours: 24)`.

## 7.4 기성금 문서 다운로드 / 스캔 업로드

기성금 탭의 각 차수 행 **PDF** 열에서:

- **[납품확인서]**: 납품확인서 PDF(서명란 공란) 미리보기/다운로드
- **[사진대지]**: 사진대지 PDF
- **[스캔업로드]**: 서명받은 종이 납품확인서 스캔본(PDF) 업로드

스캔 업로드 시:
- PDF 파일만 허용(MIME 또는 .pdf 확장자). 아니면 "PDF 파일만 업로드할 수 있습니다."
- 최대 20MB. 초과 시 "파일 크기는 20MB를 초과할 수 없습니다."
- 성공 시 "서명본 스캔이 업로드되었습니다. 이후 다운로드 시 스캔본이 제공됩니다."

> 코드 근거: `FundProgressTab.vue onScanFileSelected`, `baseline.service.ts uploadConfirmationScan`.

## 7.5 기성금 수금 확인

### 단계별 조작

1. 기성금 탭 목록에서 해당 차수 행 확인
2. 상태가 **승인(APPROVED)** 인 행의 **수금확인** 열에서 **[수금확인]** 버튼 클릭

3. **기성금 입금확인** 모달에서 정보 입력:

| 필드 | 의미 | 필수 | 제약 | 비고 |
|------|------|:---:|------|------|
| 입금일 | 실제 입금 날짜 | 필수 | 오늘 이전(max=today) | 기본값 오늘 |

| 비고 | 추가 메모 | 선택 | - | - |

4. (선급금 차감이 있는 경우) 모달에 **선급금 차감액 / 실수금액(입금 예정액)** 과 **정산 현황(수금 확인 후 선급금 정산 누계·미정산 잔액)** 이 함께 표시됩니다.
5. **[수금 확인]** 버튼 클릭 → 성공 메시지 후 자동 닫힘
6. 상태: **PAID (수금완료)**

> 📷 [스크린샷: 기성금 입금확인 모달 — 기성금 금액/(-)선급금 차감액/(=)실수금액 + 정산 현황 + 입금일·입금 금액·입금 계좌·비고]

# 8. 자금 관리 - 잔금 및 OEM

## 8.1 잔금 개요

잔금은 **납품완료 후** 정산되는 나머지 금액입니다. 계약의 마지막 수금 단계로, 발주 1건당 **1회만** 등록할 수 있습니다.

### 잔금 계산식

```
잔금 = 계약총액 − 선급금 − 기성금누계
```

시스템은 잔금을 두 가지 기준으로 동시에 계산해 둡니다. (백엔드 `BalanceInfo` 기준)

| 계산 기준 | 코드값 | 계산식 | 설명 |
|-----------|--------|--------|------|
| **신청 기준** | `REQUESTED` | 계약총액 − 선급금(신청) − 기성금누계(신청) | 신청된(청구된) 금액을 기준으로 계산 |
| **입금 기준** | `PAID` | 계약총액 − 선급금(입금) − 기성금누계(입금) | 실제 입금된 금액을 기준으로 계산 |

> **참고**: 잔금 탭의 "잔금 예정액" 은 서버에서 내려온 `balanceAmount`(잔여분)를 그대로 표시합니다. 잔여분이므로 실제 수금 여부와 무관하게 "아직 받아야 할 금액" 을 의미합니다.

### 잔금에 영향을 주는 선급금 차감

기성금 수금 시 미정산 선급금이 남아 있으면 **선급금 차감액** 이 발생하고, 잔금 단계에도 다음 항목이 함께 표시됩니다.

| 항목 | 의미 |
|------|------|
| 잔금 등록액 | 등록한 잔금 청구 금액 |
| 선급금 차감액 | 잔금에서 차감되는 미정산 선급금 (빨간색 `-` 표시) |
| 실수금액 | 잔금 등록액 − 선급금 차감액 (실제 입금 예정 금액) |

## 8.2 잔금 등록

잔금은 별도 "신청/승인" 절차 없이 **등록(생성) → 입금확인** 의 2단계로 처리됩니다.

> 📷 [스크린샷: 잔금 탭 - "잔금등록" 버튼이 활성화된 상태]

### 접근 경로
- 자금 상세 화면(`/admin/funds/{자금ID}`) → **잔금** 탭

### 등록 조건 (버튼 노출 규칙)

잔금 탭의 **[잔금등록]** 버튼은 다음 조건을 모두 만족할 때만 보입니다. (`FundBalanceTab` 기준)

1. **납품완료 상태**(`isDeliveryCompleted = true`) — 모든 출하의 납품확인이 끝나고 납품완료계가 완료되어야 함
2. 아직 **잔금 요청이 없음**(`hasBalanceRequest = false`)
3. 아직 **잔금 입금일이 없음**(`balancePaidDate` 없음)

> 납품완료 전이라면 잔금등록 버튼 대신 **[납품완료 처리하기]** 버튼이 표시됩니다. 먼저 납품완료 처리를 끝내야 잔금 등록이 가능합니다.

### 등록 절차

1. 잔금 탭에서 **[잔금등록]** 버튼 클릭
2. **잔금 등록 모달** 에서 입력
3. **[잔금 등록]** 버튼 클릭
4. 등록 완료 → 잔금 상태가 **"등록완료 (입금대기)"** 로 표시됨

> 모달 안내문: "잔금을 등록합니다. 등록 후 별도로 '잔금 입금확인'을 진행해야 입금 완료 처리됩니다."

### 입력 필드 (잔금 등록 모달)

| 필드 | 필수 | 설명 |
|------|------|------|
| 잔금 등록액 | 필수 | 등록할 잔금 금액 (자동 계산된 예정액이 초기값으로 채워짐, 수정 가능) |
| 등록일 | 필수 | 잔금 등록 날짜 (기본값: 오늘) |
| 비고 | 선택 | 메모 사항 |

### 버튼 / 동작

| 버튼 | 동작 |
|------|------|
| 잔금 등록 | 잔금 요청 레코드 생성 (등록액 > 0, 등록일 입력 시에만 활성화) |
| 취소 | 모달 닫기 |

## 8.3 잔금 입금확인 (수금 확인)

잔금을 등록한 뒤 실제로 돈이 입금되면 **잔금 입금확인** 을 진행해 수금 완료(PAID) 처리합니다.

> 📷 [스크린샷: 잔금 탭 하단의 "잔금 입금확인" 큰 초록 버튼 + 잔금 등록 정보]

### 절차

1. 잔금 탭 하단의 **[잔금 입금확인]** 버튼 클릭 (잔금 등록이 되어 있고 아직 입금완료(PAID)가 아닐 때만 표시)
2. **입금확인 모달**(공용 수금확인 모달, 제목 "잔금 입금확인")에서 입금 정보 입력
3. **[수금 확인]** 버튼 클릭
4. 완료 시 "잔금 입금 완료" 표시로 바뀜

> 잔금 등록 없이 입금확인을 시도하면 **"잔금 등록이 먼저 필요합니다."** 안내가 뜹니다.

### 입력 필드 (입금확인 모달)

| 필드 | 필수 | 설명 |
|------|------|------|
| 입금일 | 필수 | 실제 입금 날짜 (미래 날짜 선택 불가, 기본값 오늘) |
| 입금 금액 | 필수 | 실제 입금 금액. **[전액 입력]** 버튼으로 목표 금액 자동 입력 가능 |
| 입금 계좌 | 선택 | 예: 국민은행 123-456-789012 |
| 비고 | 선택 | 메모 |

> "남은 금액" 표시: 목표 금액(승인/실수금액) − 입력 금액 을 실시간으로 보여줍니다. 부분 입금도 가능합니다.

### 사용 예시 (잔금 계산)

| 항목 | 금액 |
|------|------|
| 계약총액(품대계) | 100,000,000원 |
| (−) 선급금 | 30,000,000원 |
| (−) 기성금 누계 | 50,000,000원 |
| **(=) 잔금 예정액** | **20,000,000원** |

만약 미정산 선급금이 2,000,000원 남아 잔금에서 차감된다면:

| 항목 | 금액 |
|------|------|
| 잔금 등록액 | 20,000,000원 |
| (−) 선급금 차감액 | 2,000,000원 |
| **(=) 실수금액 (입금 예정)** | **18,000,000원** |

### 오류 메시지 & 대응 (잔금)

| 메시지 | 발생 상황 | 원인 | 대응 |
|--------|-----------|------|------|
| 납품완료된 발주만 잔금 등록이 가능합니다. | 잔금 등록 시도 | 납품완료 전 상태 | 먼저 납품완료 처리 진행 |
| 납품완료 상태에서만 잔금 입금확인이 가능합니다. | 잔금 입금확인 시도 | 납품완료 전 상태 | 납품완료 처리 후 재시도 |
| 잔금 등록이 먼저 필요합니다. | 입금확인 버튼 클릭 | 잔금 미등록 | 먼저 [잔금등록] 진행 |
| 승인 상태에서만 수금 확인이 가능합니다. | 입금확인 시도 | 요청 상태가 수금확인 가능 단계가 아님 | 상태 확인 후 재시도, 지속 시 관리자 문의 |
| 입금일을 선택해주세요. / 입금 금액을 입력해주세요. | 모달 제출 | 필수 항목 누락 | 빈 필드 입력 |

## 8.4 OEM 지급 개요

OEM 지급은 **협력업체(제조사)에 지급** 하는 금액입니다. 일반적으로 **기성금의 70%** 를 지급합니다.

```
OEM 지급 예정액 = 기성금 누계 × 70%
```

> 화면 표기: OEM 지급 탭의 "OEM 지급 예정 (예정원가)" 은 `기성금누계 × 0.7` 로 자동 계산되어 표시됩니다.

### 중요 — 지급 관리 위치 변경 (읽기 전용 탭)

현재 자금 상세의 **OEM 지급 탭은 "읽기 전용"** 입니다. 실제 OEM 지급 등록/완료/취소는 **제조생산 > 월별 매출원장** 에서 관리합니다.

| 화면 | 역할 |
|------|------|
| 자금 상세 → OEM 지급 탭 | OEM 지급 현황 **조회**, 원가 재계산, B급 조정 |
| 제조생산 → 월별 매출원장 (`/admin/oem/monthly-ledger`) | OEM 지급 요청 → 확인 → 완료 **관리** |
| 제조생산 → OEM 대시보드 (`/admin/oem/dashboard`) | OEM 제조사별 발주/생산/재고/지급 통합 현황 |

> 📷 [스크린샷: 자금 상세 OEM 지급 탭 - 다크 요약 카드 + "월별 매출원장 바로가기" 안내 배너]

## 8.5 OEM 지급 탭 (조회 / 원가 재계산 / B급 조정)

### 접근 경로
- 자금 상세 화면 → **OEM 지급** 탭

### 화면 구성 (OEM 지급 요약 카드)

| 항목 | 설명 |
|------|------|
| 기성금 누계 | 청구된 기성금 합계 |
| OEM 지급 예정 (예정원가) | 기성금 누계 × 70% (또는 DB 저장 예정총액) |
| 지급 완료 | 실제 지급 완료(PAID)된 금액 합계 |
| 미지급 | 지급 예정 − 지급 완료 |

그 아래 **자금관리 기준 OEM 지급 이력** 표(읽기 전용)에 차수 / OEM 업체 / 지급예정금액 / 예정일 / 실제지급금액 / 지급일 / 상태가 표시됩니다.

| OEM 지급 상태 | 라벨 |
|---------------|------|
| `PENDING` | 지급예정 |
| `PAID` | 지급완료 |

### 버튼 / 동작

| 버튼 | 동작 | 비고 |
|------|------|------|
| 원가 재계산 | OEM 예정총액을 현재 원가 기준으로 재계산 | 원가 변동이 없으면 비활성("현재 원가와 동일합니다"), 납품완료 정보 없으면 비활성 |
| B급 조정 | B급(등외품) 품목 수량/금액 조정 | 출하 상태가 COMPLETED일 때만 가능 |
| 월별 매출원장 | `/admin/oem/monthly-ledger` 이동 | 실제 지급 관리 화면으로 이동 |

### 원가 재계산 사용 예시

OEM 원가가 변경되면 OEM 지급 탭 상단에 **노란 경고 배너** 가 뜹니다.

> "OEM 원가가 변경되어 재계산이 필요합니다 — 현재: 6,400,000원 → 재계산 시: 6,800,000원 (+400,000원)"

1. 배너 또는 헤더의 **[원가 재계산]** 버튼 클릭
2. 확인 창: "OEM 예정총액을 현재 원가 기준으로 재계산합니다." → 확인
3. 완료 시 "재계산이 완료되었습니다." 안내

> 재계산은 먼저 **미리보기**(DB 변경 없음)로 차이를 보여준 뒤 실행됩니다. 실행 전에는 DB 값이 바뀌지 않습니다.

### 오류 메시지 & 대응 (OEM 지급 탭)

| 메시지 | 발생 상황 | 원인 | 대응 |
|--------|-----------|------|------|
| 재계산에 실패했습니다. | 원가 재계산 실행 | 서버 처리 오류 | 잠시 후 재시도, 지속 시 관리자 문의 |
| 존재하지 않는 자금 관리 정보입니다. | OEM 조회/재계산 | 자금 정보 없음/삭제됨 | 목록 새로고침 후 재진입 |
| 존재하지 않는 OEM 지급 이력입니다. | 지급 처리 | 대상 지급건 없음/삭제됨 | 화면 새로고침 |
| 이미 지급 완료된 내역입니다. | 지급 완료 재시도 | 이미 PAID 상태 | 새로고침 후 상태 확인 |

## 8.6 OEM 지급 관리 (월별 매출원장)

실제 OEM 지급 요청·확인·완료는 **제조생산 > 월별 매출원장** 에서 처리합니다.

| 구분 | 내용 |
|------|------|
| **메뉴 경로** | 제조생산 → 월별 매출원장 |
| **라우트** | `/admin/oem/monthly-ledger` |

> 📷 [스크린샷: 월별 매출원장 - OEM 제조사 선택 + 연월 선택 + 원장 표 + 지급요청/확인/완료 버튼]

### 원장 화면 구성 — 지급 예정 금액은 이렇게 계산됩니다

원장 표 아래 합계 영역에 다음 행이 차례로 표시됩니다. **금액이 0 인 행은 표시되지 않습니다.**

| 표시 행 | 부호 | 내용 |
|---------|:----:|------|
| **합계** | 기준 | 해당 월 발주 품목 합계 (수량 × 원가) |
| 비출하 재고 소진 | **+** | 발주서 없이 재고에서 빠져나간 물량(품질관리 발송 / 리드파워 계약). 확정된 건만 실림 |
| 운송비 | **+** | 운송비 부담이 **「OEM 에 지불」** 인 출하의 배송비 (행 옆에 건수·운송사명 표시) |
| 가공비 | **+** | 발주서에 입력한 가공비. **발주일 기준월** 에 실림 (행 옆에 건수 표시) |
| 손실 차감 (제조사 부담) | **−** | 제조사가 부담하는 손실·스펙오납 정산분 (행 옆에 건수 표시) |
| **공급가액** | = | 위 가산·차감을 모두 반영한 지급 예정 공급가액 |
| 부가세 | + | 공급가액의 10% |
| **합계 (부가세 포함)** | = | 공급가액 + 부가세 |

```
지급 예정 공급가액 = 발주 합계 + 비출하 소진 + 운송비 + 가공비 − 손실 차감
부가세            = 공급가액 × 10%   (원 단위 반올림)
합계(VAT 포함)     = 공급가액 + 부가세
```

> **「공급가액」 행은 가산·차감이 하나라도 있을 때만 나타납니다.** 아무 조정도 없는 달은 맨 위 **합계** 가 곧 공급가액입니다.

> **가산 항목과 차감 항목은 부호가 반대입니다.** 소진·운송비·가공비는 제조사에 **더 줄 돈**, 손실 차감은 제조사에서 **뺄 돈** 입니다.

> **손실 차감은 정산 처리된 건만 반영됩니다.** 손실을 등록만 하고 [9.4.4 정산 처리](#944-정산-처리--차감--면제)에서 **[차감]** 을 누르지 않으면 이 원장에 나타나지 않습니다.

### 지급 요청 금액은 서버가 다시 계산합니다

**[지급요청]** 을 누르면 화면이 보낸 숫자를 그대로 저장하지 않고, **서버가 그 달 원장을 다시 계산해 지급 예정 공급가액을 확정**합니다.

- 그래서 **화면에 보이는 「공급가액」과 실제 요청 금액이 어긋나지 않습니다.**
- 화면 값과 서버 계산값이 다르면 서버 계산값으로 저장되고, 그 사실이 서버 로그에 남습니다.
- 확인 문구에도 지급 예정 공급가액이 그대로 나옵니다.
  → *"2026-09 매출원장 기준 12,340,000원 지급을 요청하시겠습니까?"*

> **부가세는 요청 금액에 포함되지 않습니다.** 지급 요청·기록에 쓰이는 값은 **공급가액** 입니다.

### 절차

1. **OEM 제조사** 선택 (OEM 담당자 계정은 자사로 자동 고정·잠금)
2. **연월(YYYY-MM)** 선택 후 원장 조회
3. 표시된 **지급 예정 공급가액**을 기준으로 **[지급 요청]**
4. 관리자가 **[지급 확인]** → **[지급 완료]** 순으로 처리
   - 지급 완료 시 **실제 송금액**은 고칠 수 있습니다. 기본값은 지급 예정 공급가액입니다.

### 지급 상태 흐름

| 상태 | 코드값 | 라벨 |
|------|--------|------|
| 미요청 | `NONE` | 미요청 |
| 요청 | `PENDING` | 요청완료 |
| 확인 | `CONFIRMED` | 확인완료 |
| 완료 | `PAID` | 지급완료 |

### 버튼 / 동작 및 확인 문구

| 버튼 | 확인 문구 | 결과 안내 |
|------|-----------|-----------|
| 지급 요청 | "{연월} 매출원장 기준 {금액} 지급을 요청하시겠습니까?" | "지급 요청이 등록되었습니다." |
| 요청 취소 | "지급 요청을 취소하시겠습니까?" | "지급 요청이 취소되었습니다." |
| 지급 확인 | "지급을 확인하시겠습니까?" | "지급이 확인되었습니다." |
| 지급 완료 | (완료 모달에서 금액·일자 입력) | "지급이 완료되었습니다." |

### 오류 메시지 & 대응 (월별 매출원장)

| 메시지 | 발생 상황 | 원인 | 대응 |
|--------|-----------|------|------|
| OEM 제조사를 선택하세요. | 원장 조회 | 제조사 미선택 | 제조사 선택 후 조회 |
| 원장 조회에 실패했습니다. | 원장 조회 | 서버/네트워크 오류 | 잠시 후 재시도 |
| 지급 요청에 실패했습니다. | 지급 요청 | 서버 처리 오류 | 새로고침 후 재시도 |
| 요청 취소에 실패했습니다. | 요청 취소 | 이미 처리됨/상태 변경 | 새로고침 후 상태 확인 |
| 지급 확인에 실패했습니다. / 지급 완료에 실패했습니다. | 확인·완료 | 상태 불일치 | 새로고침 후 재시도 |

| 구분 | 내용 |

연도 필터로 특정 연도 현황만 조회할 수 있으며, 품목별 생산 현황(발주/생산/입고/출고/잔여재고/생산률)도 함께 제공됩니다.

## 8.8 자금 현황 요약 (상단 카드)

자금 상세 화면 상단에서 전체 자금 현황을 한눈에 확인합니다.

| 항목 | 설명 |
|------|------|
| 계약총액 | 총 계약 금액 (품대계 기준) |
| 선급금 | 선급금 금액 (미정산 잔액 별도 표시) |
| 기성금 누계 | 청구된 기성금 합계 |
| 잔금 | 남은 정산 금액 (잔금 예정액) |
| OEM 지급 | 협력업체 지급 현황 |
| **수금률** | (선급금 + 기성금 + 잔금) 입금액 ÷ 계약총액 × 100% |

> **금액 기준 (중요)**: 모든 매출·계약총액·잔금·대시보드 합계는 **품대계(`item_total_amount`)** 를 단일 기준으로 사용합니다. 고객에게 실제 수금되는 금액이 품대계이기 때문입니다.

## 9.1 OEM 발주서 등록 — 생산자 귀속 · 가공비

### 접근 경로
- **메뉴**: 제조생산 → 발주서 관리 → 상단 **[등록]**
- **화면 주소**: `/admin/purchase-order/register` (상세/수정은 `/admin/purchase-order/detail/{발주서ID}`)

> 📷 [스크린샷: 발주서 등록 화면 — 공급원 선택 + 본사 선택 시 나타나는 경고 패널(생산자 지정) + 가공비 입력란]

### 생산자(실제 제조사) 지정

발주서의 **명의(공급원)** 와 **실제로 물건을 만든 회사**가 다를 수 있습니다. 본사(리드파워) 명의로 발주서를 끊는 경우가 그렇습니다.

| 공급원(명의) | 생산자 입력란 | 규칙 |
|--------------|---------------|------|
| 본사(리드파워) | **표시됨 · 필수** | 실제 제조사를 반드시 지정 |
| 제조사(OEM) | 표시 안 됨 | 명의가 곧 생산자. 따로 지정할 수 없음 |

**왜 필요한가 — 돈이 가는 곳이 생산자이기 때문입니다.**
- 본사는 생산 설비가 없어 **지급 대상이 될 수 없습니다.** 제조사 원가 마스터에도 본사 행이 없습니다.
- 원가 조회와 OEM 월별 원장 귀속이 **생산자 기준**으로 잡힙니다. 생산자를 비워 두면 그 발주서의 품목 단가가 전부 0원으로 저장되고, 그 0원이 그대로 원장에 실립니다.

### 단계별 조작 — 본사 명의 발주서 등록

1. **공급원** 에서 본사(목록에 `[본사 직접입고용]` 이 붙어 있는 회사)를 선택합니다.
2. 아래에 주황색 경고 패널이 펼쳐집니다.
   > **선택된 제조사는 본사로 다음과 같이 처리되니 주의 바랍니다**
   > - 발주서 상세 화면에 **"바로 입고"** 버튼이 노출됩니다.
   > - 바로 입고 시 모든 품목이 본사 창고에 즉시 입고되며 **되돌릴 수 없습니다**.
   > - 외부 OEM 발주라면 다른 제조사를 선택해 주세요.
3. 패널 안의 **생산자** 드롭다운에서 실제 제조사를 고릅니다. **(필수)**
   - 안내 문구: *"이 물량을 실제로 만든 제조사입니다. 원가와 지급이 이 회사 기준으로 잡힙니다."*
   - 목록에는 **제조사로 등록된 회사만** 나옵니다(본사·운송사 제외).
4. 품목을 추가하면 **생산자 기준 원가**가 자동으로 채워집니다.
5. 발주일자·납기 예정일·가공비·비고를 입력하고 **[저장]** 합니다.

> **공급원을 바꾸면 생산자 선택은 초기화됩니다.** 제조사 명의로 되돌렸는데 이전 생산자가 남아 있으면 저장이 거부되므로, 시스템이 미리 비웁니다.

### 발주서 단가 = 발주일 기준 제조사 원가

발주서 품목의 단가는 **그 제조사의 원가**이며, 기준일은 **발주일**입니다(출하일이 아닙니다).
같은 품목이라도 제조사마다 원가가 다르므로, 제조사를 바꿔 발주하면 그 회사 원가로 들어갑니다.

| 예: HYDRO-22-90T (2026-09 기준) | 원가 |
|---|---|
| (주)금성인슈텍 | 18,900원 |
| ㈜정우산업 | 21,600원 |
| 신원하이테크(주) | 18,405원 |

원가 구간표는 [9.2 제조사 원가 관리](#92-제조사-원가-관리-적용기간-구간표)에서 관리합니다.
발주일이 속한 구간의 원가가 자동으로 적용됩니다.

> **출하 수정으로 자동 생성되는 「보정 발주서」도 같은 규칙**입니다. 접수된 발주서가 있는 출하의
> 수량을 늘리면 늘어난 분만큼 보정 발주서가 자동 생성되며, 단가는 발주일 기준 제조사 원가로 잡힙니다.

> 판매단가(고객에게 받는 금액)와 혼동하지 마세요. 발주서는 **우리가 제조사에 주는 돈**,
> 출하 금액은 **고객에게 받는 돈**(계약 단가)입니다.

### 발주서 진행 단계 — 발행 → 접수 → 생산완료(입고)

발주서를 만들었다고 바로 출고할 수 있는 게 아닙니다. 아래 순서를 거쳐야 출하가 나갑니다.

| 단계 | 버튼 | 상태 | 이 단계가 끝나야 되는 일 |
|------|------|------|--------------------------|
| 1. 발행 | **[저장 후 발행]** | 발주 | 발주서 PDF 생성 |
| 2. 접수 | 발주서 상세 **[접수]** | 접수 | **출하의 [출고요청] 버튼이 열림** |
| 3. 생산완료 | **[생산완료 체크] → [생산완료 저장]** | 생산완료 | **입고 반영 → 운송 등록 가능** |

- **[저장]** 만 누르면 작성중(DRAFT)으로 남습니다. 작성중 발주서는 출고요청·원장 어디에도 잡히지 않습니다.
- 접수는 원래 제조사가 하는 절차이지만, 관리자가 발주서 상세에서 대신 처리할 수 있습니다.
- **[생산완료 체크]** 를 누르면 발주수량이 그대로 채워지고, **[생산완료 저장]** 시 그 수량이 제조사 창고에 입고됩니다.

> 출하 쪽에서 무엇이 막혀 있는지는 [3.3 출고요청](#33-출고요청-운송-등록-전-필수)을 보세요.

### 가공비

제조사에 **가공을 요청하고 지불하는 비용**입니다. 수량 × 원가와는 별개로 **금액만** 더해집니다.

| 항목 | 내용 |
|------|------|
| 붙는 단위 | **발주서 1건당 하나** (품목별 아님) |
| 원장 반영 월 | **발주일 기준월** (출하일이 아님) |
| 원장 귀속 | 생산자 기준 (생산자가 없으면 공급원) |
| 원장에 실리는 조건 | 가공비 > 0 이고, 발주서 상태가 **작성중(DRAFT)·반려·삭제가 아닐 것** |
| 부가세 | **과세 대상.** 공급가액에 합산된 뒤 10%가 매겨집니다 |

> ⚠ **작성중(DRAFT) 상태 발주서의 가공비는 원장에 실리지 않습니다.** 발주서를 **발행**해야 그 달 원장에 나타납니다.

#### 넣을 수 있는 곳 — 세 군데

| 화면 | 언제 |
|------|------|
| **발주서 등록** | 처음부터 금액을 아는 경우 |
| **발주서 상세 → [수정]** | 나중에 협의가 끝나 확정된 경우 |
| **출하 사후 처리** | 출하를 통해 발주서를 찾아갈 때 |

셋 다 같은 값을 고치는 것입니다.

#### 발주서 PDF 에 나오는 모습

품목 표 **마지막 행**에 붙고 **공급가액에 합산**됩니다.

```
1   HYDRO-22-40T    118    10,000    1,180,000
4   HYDRO-22-110T   576    26,400   15,206,400
──────────────────────────────────────────────
    가공비   OEM 가공 비용 (발주 건 단위)   300,000
──────────────────────────────────────────────
                        공급가액   20,113,600
                        부가세      2,011,360
                        합계       22,124,960
```

- 가공비가 **0원이면 이 행은 나오지 않습니다.**
- 이렇게 해야 제조사가 받는 발주서 금액과 **월별 원장의 지급액이 맞아떨어집니다.**

> ⚠ **PDF 는 발행 시점에 파일로 저장됩니다.** 가공비를 나중에 넣거나 고쳤다면 **발주서를 다시 발행해야** 새 금액이 반영된 PDF 가 나옵니다.

#### 0 으로 되돌리려면

가공비를 잘못 넣었다면 입력란을 **비우지 말고 `0` 을 넣으세요.**

빈 칸으로 저장하면 서버가 "값을 안 보냈다"로 읽어 **기존 금액이 그대로 남습니다.** 화면에서는 비워도 저장 시 0 으로 바뀌도록 되어 있지만, 확실하게 하려면 0 을 직접 입력하는 편이 좋습니다.

### 입력 필드 설명 (생산자·가공비 관련)

| 필드 | 필수 | 설명 |
|------|:----:|------|
| 공급원 | O | 발주서 명의. 제조사 또는 본사. **OEM 담당자 계정은 선택이 잠깁니다**(아래 참고) |
| 생산자 | 조건부 O | **본사 명의일 때만** 표시·필수. 실제 제조사 |
| 가공비 | - | 제조사에 지급할 가공 비용. 기본 0. 발주일 기준월 원장에 가산 |

> **OEM 담당자 계정으로 로그인한 경우** — 공급원 드롭다운이 잠기고 *"본인 소속 회사로 자동 설정됩니다."* 안내가 표시됩니다. 선택 가능한 회사가 1건일 때 본인 회사가 자동 선택됩니다.
>
> ⚠️ 확인 필요: 자동 선택은 **공급원**에만 적용되며 **생산자**를 자동 세팅하지는 않습니다. OEM 담당자는 제조사 명의로 등록하게 되므로 생산자 입력란 자체가 나타나지 않습니다.

### 오류 메시지 & 대응 (생산자·가공비)

| 메시지 | 원인 | 대응 |
|--------|------|------|
| 본사 명의 발주서는 생산자(실제 제조사)를 지정해야 합니다. | 저장 전 화면 검증 — 본사 선택 후 생산자 미지정 | 경고 패널의 생산자 드롭다운에서 제조사 선택 |
| 본사(리드파워) 명의 발주서는 생산자(실제 제조사)를 지정해야 합니다. 본사는 생산 설비가 없어 지급 대상이 될 수 없습니다. (발주서: PO202609-001) | 서버 검증 — 생산자 없이 본사 명의 저장 시도 | 괄호 안 발주서 번호를 찾아 생산자 지정 |
| 제조사 명의 발주서에는 생산자를 따로 지정할 수 없습니다. 생산자가 다르면 본사(리드파워) 명의로 등록하세요. | 제조사 명의인데 생산자가 함께 전송됨 | 공급원을 본사로 바꾸거나 생산자를 비움 |
| 생산자는 제조사로 등록된 회사만 지정할 수 있습니다. (현재 유형: CARRIER) | 제조사가 아닌 회사를 생산자로 지정 | 기초정보에서 해당 회사 유형 확인 |
| 공급원(제조사)은 필수입니다. | 공급원 미선택 | 공급원 선택 후 재시도 |
| DRAFT 또는 ISSUED 상태의 발주서만 수정할 수 있습니다. 현재 상태: COMPLETED | 진행된 발주서 수정 시도 | 수정 불가. 별도 처리 필요 |

## 9.2 제조사 원가 관리 (적용기간 구간표)

### 접근 경로
- **메뉴**: 기초정보 → 제조사 원가
- **화면 주소**: `/admin/basic-info/oem-cost`

> 📷 [스크린샷: 제조사 원가 화면 — 상단 통계 카드 4종 + SKU 트리 목록(펼치면 제조사별 원가 행) + 상태 배지]

### 원가는 "현재값 1개" 가 아니라 "기간별 구간표" 입니다

하나의 SKU·제조사 조합에 **여러 개의 원가 구간**이 쌓입니다. 각 구간은 *언제부터 언제까지 얼마* 를 뜻합니다.

- 목록에는 **적용중 구간과 만료된 구간이 모두** 나옵니다.
- 정렬은 **제조사별로 묶이고, 그 안에서 최신 적용 시작일이 위**로 옵니다.
- 발주·출하 금액은 **그 시점에 유효했던 구간**의 원가로 계산됩니다. 과거 건이 오늘 원가로 덮이지 않습니다.

### 상태 표기

| 상태 배지 | 판정 기준 |
|-----------|-----------|
| **적용중** | 적용 시작일이 지났고, 종료일이 없거나 아직 지나지 않음 |
| **만료됨** | 종료일이 이미 지남 |
| **적용예정** | 적용 시작일이 아직 오지 않음 |

> **"종료일이 있는가" 가 아니라 "이미 지났는가" 로 판정합니다.** 예를 들어 `6/1 ~ 12/31` 구간은 종료일이 있어도 오늘이 그 안이면 **적용중** 입니다.

### 상단 통계 카드

| 카드 | 내용 |
|------|------|
| 총 원가 설정 | 등록된 원가 행 수 |
| 적용중 | 현재 적용중인 원가 수 |
| 원가 미설정 SKU | 원가가 하나도 없는 SKU 수 |
| 30일내 만료 | 30일 안에 종료일이 도래하는 원가 수 |

### 버튼이 하는 일 — 새 구간은 [+], 값 손질은 [수정]

원가 행의 버튼은 역할이 갈려 있습니다. **새 구간을 만드는 건 [+] 하나뿐**입니다.

| 버튼 | 하는 일 | 어디에 |
|------|---------|--------|
| **[+]** | **새 구간 추가** — 「지금부터 적용」 / 「지난 기간」 중 선택 | 제조사별 **적용중 행 한 곳** |
| **[수정]** | 그 구간의 **금액을 그 자리에서 정정** (새 구간 안 생김) | 모든 구간 행 |
| **[이력]** | 변경 이력 보기 | 모든 구간 행 |
| **[삭제]** | 구간 삭제 | **마지막 구간만** |

> 만료된 구간 행에는 **[수정] [이력]** 만 나옵니다. [+]는 제조사당 하나면 되고(어느 행에서 눌러도 결과가 같습니다), 삭제는 마지막 구간에서만 가능하기 때문입니다.

### 단계별 조작 — 원가가 바뀌었을 때 (지금부터 적용)

1. 목록에서 해당 SKU 행을 펼쳐 제조사의 **적용중** 행을 찾습니다.
2. **[+]** 를 누릅니다. → **"원가 구간 추가"** 모달
3. **「지금부터 적용」** 카드를 고릅니다. *(단가가 올랐거나 내렸을 때)*
4. **적용 시작일**(기본값 오늘)과 새 **원가** 를 입력합니다. 종료일은 비우면 무기한입니다.
5. 안내로 무슨 일이 일어날지 미리 확인합니다.
   > *"**2026-07-01 ~ 무기한** 은 **2026-09-30** 까지로 자동 마감되고, 입력한 시작일부터 새 원가가 적용됩니다. 이전 구간은 지워지지 않아 그 기간의 발주·출하는 계속 옛 원가로 계산됩니다."*
6. **[구간 추가]** 를 누릅니다.

**결과**: 이전 구간이 **새 시작일의 전날까지로 자동 마감**되고 **새 구간이 추가**됩니다. 이전 구간은 삭제되지 않으므로 그 기간의 발주·출하 금액은 그대로 유지됩니다.

> 원가가 실제로 바뀌면 저장 직후 **재계산 안내 모달**이 이어서 뜹니다.

### 단계별 조작 — 지난 기간 단가를 뒤늦게 받았을 때 (소급 구간)

제조사가 **지나간 기간의 단가표**를 나중에 보내오는 경우에 씁니다.

1. 적용중 행의 **[+]** → **「지난 기간」** 카드를 고릅니다.
2. **적용 시작일과 종료일을 모두** 넣습니다. **종료일은 필수** 입니다 — 비우면 무기한이 되어 뒤 구간과 겹칩니다.
   - 모달이 현재 등록된 구간을 보여주고 *"종료일은 **2026-06-30** 이전이어야 합니다"* 로 범위를 알려줍니다.
3. **원가** 를 입력합니다. 두께가 있는 품목이면 **T당 단가로 환산**해 보여줍니다(제조사 단가표가 T당으로 오는 경우가 많습니다).
4. **[구간 추가]** 를 누릅니다.

> ⚠ **이미 등록된 출하 금액은 바뀌지 않습니다.** 출하는 등록 시점의 원가를 그대로 들고 있습니다.
> 과거분 금액까지 바로잡으려면 저장 후 **원가 재계산**을 따로 돌려야 합니다.

**기간이 겹치면 저장이 거부됩니다.**
> *"적용기간이 기존 구간과 겹칩니다. 입력하신 구간: 2026-06-01 ~ 2026-09-30 / 겹치는 구간: 2026-08-01 ~ 무기한 (원가 16,362원). 겹치는 구간을 먼저 정리한 뒤 다시 시도하세요."*

### 단계별 조작 — 금액이 잘못 들어갔을 때 (원가 정정)

구간은 맞는데 **금액만 잘못 입력된 경우**에 씁니다.

1. 해당 구간 행의 **[수정]** 을 누릅니다.
2. 모달이 **"원가 정정"** 으로 열립니다. 부제는 *"지나간 구간의 금액을 그 자리에서 정정"*.
3. 금액과 비고를 고칩니다. **새 구간이 생기지 않습니다.**
4. 경고를 확인합니다.
   > ⚠ *"**2026-01-01 ~ 2026-06-30** 구간의 금액을 그 자리에서 고칩니다. 새 구간이 생기지 않습니다. 이 기간의 발주·출하 원가가 바뀌므로, 저장 후 해당 건들의 금액을 다시 확인하세요."*
5. **[정정하기]** 를 누릅니다.

> ⚠ **정정은 소급입니다.** 그 기간의 발주·출하 원가가 통째로 바뀝니다.
> 저장 후 반드시 해당 기간의 발주서·출하·OEM 월별 원장 금액을 다시 확인하세요.

### 등록 버튼은 "첫 구간" 전용입니다

SKU 행의 **[OEM 원가 추가]** 는 그 제조사의 **첫 구간**만 만듭니다. 이미 원가가 있으면 거부됩니다.
> *"이미 등록된 OEM 원가입니다. 원가가 바뀌었다면 '수정'에서 새 적용 시작일을 넣으세요."*

이미 원가가 있는 제조사는 **[+]** 를 쓰시면 됩니다.

### 지급이 끝난 기간은 고칠 수 없습니다

제조사에게 **지급이 완료(PAID)** 된 달이 있으면, **그 달 이전 기간의 원가는 수정도 삭제도 막힙니다.** 이미 내보낸 돈과 장부가 어긋나기 때문입니다.

> ⚠ *"**2026-08** 까지 지급이 완료되어 그 이전 기간의 원가는 바꿀 수 없습니다. 적용 시작일은 **2026-09-01** 이후로 지정하세요. 이미 지급한 달을 정정해야 한다면 원가가 아니라 월별 매출원장에서 조정하세요."*

| 지급 상태 | 원가 수정 |
|-----------|-----------|
| 미요청 · 요청(PENDING) · 확인(CONFIRMED) | **가능** — 아직 돈이 나가지 않았습니다 |
| **지급 완료(PAID)** | **불가** — 그 달 이전 기간 전부 |

지급이 끝난 달을 정말 고쳐야 한다면 **원가가 아니라 월별 매출원장에서 조정 항목으로** 처리해야 합니다.

### 이력 버튼 — "적용구간" 과 "변경 이력" 은 서로 다른 것입니다

**[이력]**(시계 아이콘)을 누르면 **변경 이력**만 나옵니다 — *누가 언제 왜 고쳤나* 를 남긴 감사 로그입니다.

| 컬럼 | 내용 |
|------|------|
| 공급사명 · 유형(등록/수정/삭제) | 무엇을 했나 |
| 이전 원가 → 변경 원가 | 금액이 어떻게 바뀌었나 |
| 적용기간 · 변경자 · 변경일시 · 사유 | 언제·누가·왜 |

> **적용구간(구간표)은 목록 화면에서 봅니다.** 예전에는 이 모달 위쪽에도 적용구간 표가 있었지만, 목록이 만료 구간까지 전부 펼쳐 보여주고 거기서 바로 고칠 수 있게 되면서 걷어냈습니다. 표가 자리를 차지해 정작 변경 이력이 아래로 밀려 있었습니다.

**구간표와 변경 이력은 담는 것이 다릅니다.**

| | 목록의 구간표 | 이력 모달 |
|---|---|---|
| 무엇 | *지금 얼마인가* — **상태** | *누가 언제 왜 고쳤나* — **사건** |
| 정정했을 때 | 금액이 **덮어써짐** (이전 값은 남지 않음) | 한 줄 추가 (**이전 값이 여기에만 남음**) |

> 그래서 **같은 구간을 제자리 정정하면 이력이 유일한 흔적**이 됩니다. 목록만 보면 처음부터 그 금액이었던 것처럼 보입니다.

### 시스템 일괄 적재 감추기

이력 위쪽 **[시스템 일괄 적재 N건 보기]** 버튼이 있습니다.

- **기본은 감춰져 있습니다.** 2026-08-27 일괄 소급 반영, 2026-09-15 구간표 승급 같은 **일회성 데이터 이전**이 `system` 이름으로 한꺼번에 쌓여 있어, 그대로 두면 **사람이 실제로 한 변경이 뒤로 밀립니다.**
- 버튼을 누르면 함께 보이고, 그 행들은 **흐린 회색**으로 구분됩니다.
- **데이터를 지운 것이 아니라 보여주지 않을 뿐**입니다.

- SKU 행(부모)의 **[이력]** 은 그 SKU 의 **모든 제조사** 이력을, 제조사 행(자식)의 **[이력]** 은 그 제조사 것만 보여줍니다.

> 예전에 쌓인 일부 이력은 적용기간 항목이 비어 있어 `-` 로 표시됩니다.

### 구간 삭제

목록의 원가 행 끝 **[삭제]**(휴지통 아이콘)로 지웁니다.

- **마지막 구간만 지울 수 있습니다.** 중간 구간은 버튼이 눌리지 않고, 마우스를 올리면 이유가 나옵니다 — 지우면 그 기간의 원가를 못 찾아 출하·원장 금액이 어긋나기 때문입니다.
- **마지막(무기한) 구간을 지우면 앞 구간이 자동으로 무기한이 됩니다.** 지운 뒤 "적용중 원가가 없는" 상태가 되지 않도록 시스템이 이어 줍니다.
- **이미 나간 출하의 금액은 바뀌지 않습니다.** 출하에는 그 시점 원가가 따로 저장돼 있습니다.

### 목록의 경고 배지

적용기간 칸에 문제가 있으면 배지로 알려 줍니다.

| 배지 | 뜻 | 대응 |
|------|-----|------|
| 🟠 **겹침** | 다른 구간과 적용기간이 겹칩니다. 그 날짜의 원가를 하나로 정할 수 없어 집계가 어긋납니다 | 한쪽 구간의 기간을 고치거나 삭제해 정리 |
| 🔴 **이후 원가 없음** | 마지막 구간인데 종료일이 있습니다. 그 날 이후를 덮는 원가가 없어 **적용중 원가가 없는** 상태입니다 | 그 구간의 종료일을 비우거나, 이어지는 새 구간을 등록 |

> 두 상태 모두 **저장 단계에서 막고 있지만**, 과거에 들어갔거나 데이터를 직접 손본 건은 걸러지지 않습니다. 그래서 화면에 드러나게 했습니다.

### 막히는 경우 — 왜 막는가

| 상황 | 시스템 동작 | 왜 막는가 |
|------|-------------|-----------|
| 적용기간이 기존 구간과 겹침 | 저장 거부 | 겹치면 그 날짜의 원가가 두 개가 되어, 어느 값으로 계산될지 정해지지 않음 |
| 뒤에 다른 구간이 있는 구간을 삭제 | 삭제 거부 | 지운 자리가 구멍이 되어 그 기간 원가를 못 찾음 → 출하·원장 금액이 어긋남 |
| 적용 시작일을 과거로 되돌림 | 저장 거부 | 앞 구간과 겹침. 과거 시점 원가를 고치려면 **그 구간을 직접 정정**해야 함 |
| 이미 원가가 있는데 **[등록]** 으로 새로 추가 | 등록 거부 | 등록은 **첫 구간 전용**. 여기서 행을 만들면 앞 구간이 마감되지 않아 구간이 겹침 |
| **마지막 구간에 종료일을 넣음** | 저장 거부 | 그 날 이후를 덮는 원가가 없어져 **적용중 원가가 사라짐**. 그러면 등록도 막혀(등록은 첫 구간 전용) 화면에서 손쓸 수 없게 됨 |

> **마지막 구간은 종료일 없이(무기한) 두어야 합니다.** 원가가 바뀐 것이라면 종료일을 넣는 게 아니라 **적용 시작일에 새 날짜**를 넣으세요. 이전 구간은 자동으로 마감됩니다.

|--------|-----------|------|

## 9.3 재고 소진관리

### 9.3.1 재고 소진관리 개요

재고에서 물품이 나갔지만 **출하(납품)로 잡히지 않는** 경우를 기록하는 기능입니다. 품질관리원에 시험용으로 보내거나, 삼자단가계약처럼 출하 등록 없이 재고에서 빠져나가는 건들이 여기에 해당합니다.

소진을 **확정**하면 두 가지가 동시에 일어납니다.

1. 해당 창고·품목의 **재고가 차감**됩니다.
2. 그 물량의 **원가가 생산자(제조사)의 OEM 월별 매출원장에 가산**됩니다. 즉 **제조사에 지급할 돈이 늘어납니다.**

> 소진은 발주서(`purchase_orders`)가 없는 거래입니다. 월별 매출원장은 원래 발주서를 기준으로 집계하므로, 소진을 등록하지 않으면 그 물량의 원가가 **원장에 실릴 방법이 아예 없습니다.**

#### 출하와 소진의 차이

| 구분 | 출하(납품) | 재고 소진 |
|------|-----------|-----------|
| 대상 | 수요기관 납품 | 품질관리원 시험 발송, 리드파워 계약 납품 등 |
| 발주서 | 있음 | 없음 |
| 매출 | 발생(품대계) | **없음** |
| 재고 | 배차 시 차감 | **확정 시 차감** |
| 원장 반영 | 발주서 기준 자동 | **소진 등록·확정으로만** |
| 고객 서류 | 인수증·납품확인서 등 | 없음 |

#### 소진 유형 (3종)

| 유형 | 코드 | 설명 | 추가 입력 항목 |
|------|------|------|----------------|
| 품질관리 발송 | `QUALITY_TEST` | 품질관리원에 시험용으로 보내는 물량(보통 1매~30매) | 품질관리원 / 보낸 곳 |
| 리드파워 계약 | `LP_CONTRACT` | 우수제품계약이 아닌 **삼자단가계약** 건. 제조사에게 받아 납품하지만 출하로 등록하지 않음 | 계약번호, 납품처 |
| 기타 | `OTHER` | 위 두 가지에 해당하지 않는 소진 | 없음 |

#### 수량 단위 — 1매 = 2㎡

품목 단위가 ㎡(제곱미터)이고 원가·단가가 모두 ㎡ 기준이므로, **계산에 쓰이는 값은 언제나 ㎡** 입니다. 현장에서는 "몇 매"로 세기 때문에 등록 화면에서 **매수와 ㎡를 함께 입력**할 수 있고, **어느 쪽을 입력해도 반대쪽이 자동으로 채워집니다.**

```
1매 = 2㎡          예) 30매 = 60㎡
매수 입력 → ㎡ = 매수 × 2
㎡ 입력   → 매수 = ㎡ ÷ 2 (반올림, 참고값)
```

> 목록의 수량 칸은 `60㎡ (30매)` 처럼 ㎡를 기준으로 표시하고 매수를 괄호로 덧붙입니다.

#### 상태 흐름

```
   [등록]              [확정]                  [취소]
  ─────────▶ 작성중 ─────────▶ 확정 ──────────────▶ 취소
             DRAFT            CONFIRMED            CANCELLED
               │                 │                    │
               │ 수정 가능        │ 재고 차감됨          │ 재고 복구됨
               │ 삭제 가능        │ 원장에 실림          │ 원장에서 빠짐
               ▼                 ▼                    ▼
        재고·원장에 아무 영향 없음                  취소선 표시
```

| 상태 | 화면 표기 | 재고 | 월별 매출원장 | 가능한 작업 |
|------|----------|------|--------------|------------|
| DRAFT | 작성중 | 영향 없음 | 실리지 않음 | 수정 / 확정 / 삭제 |
| CONFIRMED | 확정 | **차감됨** | **가산됨** | 취소 |
| CANCELLED | 취소 | 복구됨 | 빠짐 | 없음(조회만) |

> **중요**: 등록만 해서는 재고가 줄지 않습니다. **확정해야 재고가 차감되고 원장에 실립니다.**

### 9.3.2 소진 목록 조회

#### 접근 경로
- **메뉴**: 제조생산 → 재고 소진관리
- **화면 주소**: `/admin/inventory/consumption`

> 📷 [스크린샷: 재고 소진관리 목록 화면 — 상단 [조회]/[소진 등록] 버튼 + 검색줄 + 목록 테이블]

#### 화면 구성

목록 컬럼(좌→우): **소진번호 · 유형 · 소진일 · 창고 · 품목 · 수량 · 생산자 · 원가 · 금액 · 보낸 곳/계약 · 상태 · 관리**

- **소진번호**: 등록 시 자동 채번됩니다. 형식은 `IC-YYYYMM-nnn` (예: `IC-202609-001`). 앞의 연월은 **소진일** 기준입니다.
- **유형 / 상태**: 색상 칩으로 표시됩니다.
- **수량**: `㎡ (매수)` 형식.
- **금액**: 수량(㎡) × 원가.
- **보낸 곳 / 계약**: 보낸 곳(`destination`)이 있으면 그 값을, 없으면 계약번호를 보여줍니다.
- **취소된 건**은 회색 취소선으로 표시됩니다.

#### 검색 조건

| 검색 항목 | 입력 방식 | 설명 |
|-----------|-----------|------|
| 유형 | 드롭다운 | 전체 / 품질관리 발송 / 리드파워 계약 / 기타 |
| 상태 | 드롭다운 | 전체 / 작성중 / 확정 / 취소 |
| 생산자 | 드롭다운 | 제조사 목록에서 선택(회사 구분이 **제조사**인 회사만 표시) |
| 소진일 | 시작일 ~ 종료일 (달력) | 소진일 기준 기간 |
| 검색어 | 텍스트 (`소진번호 / 납품처 / 계약번호`) | 소진번호·보낸 곳·계약번호 부분일치 |

#### 단계별 조작 — 조회하기

1. 제조생산 → 재고 소진관리로 이동합니다. (화면에 들어오면 자동으로 첫 페이지가 조회됩니다.)
2. 검색줄에서 유형·상태·생산자·소진일 기간·검색어 중 필요한 조건을 입력합니다.
3. 상단 우측 **[조회]** 버튼을 누르거나, 검색어 칸에서 **Enter** 를 누릅니다.
4. 결과가 20건을 넘으면 하단 페이지 버튼으로 이동합니다.

> 조건을 바꿔 조회하면 항상 **1페이지부터** 다시 보여줍니다.

#### 주요 버튼/동작

| 버튼 | 위치 | 동작 |
|------|------|------|
| 조회 | 상단 우측 | 검색 조건으로 목록 조회 (조회 중 비활성) |
| 소진 등록 | 상단 우측 | 소진 등록 모달 열기 |
| 수정 | 행 관리 칸 | **작성중** 건만 표시. 등록 모달을 수정 모드로 엶 |
| 확정 | 행 관리 칸 | **작성중** 건만 표시. 재고 차감 + 원장 반영 |
| 삭제 | 행 관리 칸 | **작성중** 건만 표시. 되돌릴 수 없음 |
| 취소 | 행 관리 칸 | **확정** 건만 표시. 재고를 되돌림 |

> 취소된 건의 관리 칸에는 `-` 만 표시됩니다.

### 9.3.3 소진 등록

#### 접근 경로
소진 등록 모달은 두 곳에서 열 수 있습니다.

1. **재고 소진관리** 화면 → 상단 우측 **[소진 등록]**
2. **재고현황**(`/admin/inventory/list`) 화면 → 상단 **[소진 등록]**
   - 이 버튼은 **OEM(제조사) 담당자 계정에는 표시되지 않습니다.**

> 📷 [스크린샷: 재고 소진 등록 모달 — 유형 버튼 3개 / 창고·품목 선택 / 매↔㎡ 수량 입력 / 생산자 / 소진일]

#### 단계별 조작 — 등록하기

1. **[소진 등록]** 을 누릅니다.
2. **소진 유형**을 버튼으로 고릅니다. (기본값: **품질관리 발송**)
3. **출고 창고**를 선택합니다. 창고를 바꾸면 품목 선택과 생산자 선택이 초기화되고, 그 창고의 재고를 다시 불러옵니다.
4. **품목(SKU)** 을 선택합니다. 선택 목록에는 **재고가 남아 있는 품목만** 나오고, 품목명 뒤에 현재고가 함께 표시됩니다.
   - 재고 있는 품목이 하나도 없으면 → *"이 창고에 재고가 있는 품목이 없습니다."*
5. **소진 수량**을 입력합니다. **매** 칸 또는 **㎡** 칸 아무 쪽이나 입력하면 반대쪽이 자동으로 채워집니다. 우측에 `현재고 ○○㎡` 배지가 함께 표시됩니다.
   - 현재고보다 많이 입력하면 배지가 빨갛게 바뀌고 → *"재고보다 많습니다. 확정할 수 없습니다."*
6. **생산자**를 확인합니다. (A.3.1 참고)
7. **소진일**을 확인·수정합니다. 기본값은 오늘이며, 아래에 `이 날짜의 원가가 적용되고, 이 달(YYYY-MM) 원장에 실립니다.` 안내가 표시됩니다.
8. 유형별 추가 항목을 입력합니다.
   - 품질관리 발송 → **품질관리원 / 보낸 곳**
   - 리드파워 계약 → **계약번호**, **납품처**
   - 기타 → 추가 항목 없음
9. 필요하면 **비고**를 입력합니다.
10. **[저장]** 을 누릅니다. 저장된 건은 **작성중(DRAFT)** 상태입니다. (**아직 재고는 줄지 않습니다.**)

> 재고현황 화면에서 특정 행을 통해 모달을 연 경우에는 **창고와 품목이 고정**되어 바꿀 수 없습니다.

#### A.3.1 생산자를 왜 지정해야 하는가

소진 물량의 **원가와 지급 귀속처**는 "누가 그것을 만들었는가"로 정해집니다.

- 출고 창고가 **제조사 창고**이면 → 그 창고의 제조사가 자동으로 생산자가 됩니다. 생산자 칸은 **선택 불가(비활성)** 상태가 되고, 안내에 *"선택한 창고의 제조사가 생산자가 됩니다."* 라고 표시됩니다.
- 출고 창고가 **제조사 창고가 아니면**(예: 리드파워 창고) → 리드파워 창고에는 생산 설비가 없으므로 시스템이 생산자를 자동으로 정할 수 없습니다. 이때 생산자는 **필수 입력**이 되고, 안내가 경고색으로 바뀝니다.

> **여기서 고른 제조사 기준으로 원가가 조회되고, 그 제조사의 월별 원장에 금액이 실립니다.** 잘못 고르면 엉뚱한 제조사에게 지급될 금액이 늘어납니다.

#### A.3.2 소진일 = 원가 기준일

소진일은 단순한 날짜 기록이 아니라 **두 가지를 동시에 결정**합니다.

| 결정하는 것 | 내용 |
|-------------|------|
| 적용 원가 | 그 날짜에 유효했던 **원가 구간**의 단가가 적용됩니다(소진일 시점 조회). |
| 원장 반영 월 | 소진일의 **연월**이 원장 반영 월이 됩니다. (예: 2026-09-15 → `2026-09` 원장) |

- 원가는 **등록·수정 시점에 스냅샷으로 박힙니다.** 나중에 원가 마스터를 고쳐도 이미 등록된 소진 건의 원가는 흔들리지 않습니다.
- **확정할 때 원가를 다시 찍지 않습니다.** 확정이 며칠 늦어져도 원가는 소진일 기준 그대로입니다.
- 작성중 건을 **수정하면 원가가 다시 계산됩니다.** 소진일을 바꾸면 적용 원가와 원장 반영 월이 함께 바뀝니다.
- 해당 생산자·품목의 원가가 등록되어 있지 않으면 **원가 0원**으로 저장되며, 이 상태로는 **확정할 수 없습니다.**

#### 입력 필드 설명

| 필드 | 필수 | 형식 | 설명 |
|------|:----:|------|------|
| 소진 유형 | O | 버튼 선택 | 품질관리 발송 / 리드파워 계약 / 기타. 기본값 품질관리 발송 |
| 출고 창고 | O | 드롭다운 | 재고가 빠져나갈 창고 |
| 품목(SKU) | O | 드롭다운 | **재고가 있는 품목만** 표시. 현재고가 함께 보임 |
| 소진 수량(매) | △ | 숫자(1 이상) | ㎡와 상호 환산. 둘 중 하나는 반드시 입력 |
| 소진 수량(㎡) | △ | 숫자(1 이상, 2단위) | **계산 기준값** |
| 생산자 | 조건부 O | 드롭다운 | 제조사 창고면 자동, 아니면 **필수 지정** |
| 소진일 | O | 날짜 | 기본값 오늘. **원가 기준일 + 원장 반영 월** |
| 품질관리원 / 보낸 곳 | - | 텍스트 | 유형이 품질관리 발송일 때만 표시 |
| 계약번호 | - | 텍스트 | 유형이 리드파워 계약일 때만 표시(삼자단가계약 번호) |
| 납품처 | - | 텍스트 | 유형이 리드파워 계약일 때만 표시 |
| 비고 | - | 여러 줄 텍스트 | 자유 기록 |

> **[저장]** 버튼은 창고·품목·수량(0 초과)·소진일이 모두 채워지고, 생산자가 필요한 경우 생산자까지 골라야 눌립니다.

#### 오류 메시지 & 대응 (등록/수정)

| 메시지 | 원인 | 대응 |
|--------|------|------|
| 소진 유형은 필수입니다. | 유형 미선택 | 유형 버튼 선택 |
| 출고 창고는 필수입니다. | 창고 미선택 | 창고 선택 |
| SKU 는 필수입니다. | 품목 미선택 | 품목 선택 |
| 소진일은 필수입니다. 원가 기준일이 됩니다. | 소진일 미입력 | 소진일 입력 |
| 소진 수량(㎡) 또는 매수를 입력하세요. | 수량 미입력 | 매수 또는 ㎡ 입력 |
| 이 창고는 제조사 창고가 아니라 생산자를 자동으로 정할 수 없습니다. 실제로 만든 제조사를 직접 지정하세요. | 리드파워 창고 등에서 생산자 미지정 | 생산자 드롭다운에서 제조사 선택 |
| 작성중(DRAFT) 상태만 수정할 수 있습니다. 현재 상태: ○○ | 확정/취소된 건 수정 시도 | 확정 건은 취소 후 새로 등록 |
| 이 창고에 재고가 있는 품목이 없습니다. | 선택한 창고에 재고 0 | 창고를 바꾸거나 입고 확인 |
| 재고보다 많습니다. 확정할 수 없습니다. | 수량 > 현재고 | 수량을 현재고 이내로 |
| 저장에 실패했습니다. | 서버·네트워크 오류 | 잠시 후 재시도, 반복 시 관리자 문의 |

### 9.3.4 확정 · 취소 · 삭제

#### A.4.1 확정하기 (재고 차감 + 원장 반영)

1. 목록에서 **작성중** 건의 **[확정]** 버튼을 누릅니다.
2. 확인창 내용을 읽고 **확인**을 누릅니다.
   > `IC-202609-001 을 확정합니다.` <br> `재고 60㎡ 가 차감되고 2026-09 원장에 1,200,000원이 반영됩니다.`
3. 처리되면 목록이 새로고침되고 상태가 **확정**으로 바뀝니다.

**[확정] 버튼이 비활성인 경우** — 버튼에 마우스를 올리면 이유가 표시됩니다.

| 툴팁 | 의미 | 대응 |
|------|------|------|
| 원가가 0원입니다. 해당 생산자·품목의 원가를 먼저 등록하세요. | 소진일 기준으로 해당 생산자·품목 원가가 없음 | 원가 마스터에 원가를 등록한 뒤 건을 **수정**해 원가를 다시 찍고 확정 |
| 재고가 부족합니다 (현재고 ○㎡ / 필요 ○㎡) | 현재고 < 소진 수량 | 수량을 줄이거나 입고 후 확정 |
| 재고를 차감하고 원장에 반영합니다. | 확정 가능 상태 | 그대로 확정 |

**확정 시 내부 처리 순서**

```
① 상태를 먼저 '확정' 으로 선점   ← 동시에 두 번 눌러도 재고가 이중 차감되지 않게 하는 장치
② 재고 차감 (입출고 이력에 기록)
   비고: "재고 소진 IC-202609-001 (품질관리 발송) — 한국건설생활환경시험연구원"
③ 재고가 모자라면 ①까지 함께 되돌아감(저장되지 않음)
```

확정된 소진은 **재고현황 → 입출고 이력**에서 위 비고로 역추적할 수 있습니다.

#### A.4.2 취소하기 (재고 복구)

1. 목록에서 **확정** 건의 **[취소]** 버튼을 누릅니다.
2. 입력창에 **취소 사유**를 입력합니다.
   > `IC-202609-001 을 취소합니다.` <br> `재고 60㎡ 가 복구되고 원장에서도 빠집니다.` <br> `취소 사유를 입력하세요.`
3. 확인하면 재고가 복구되고 상태가 **취소**로 바뀝니다. 목록에서는 취소선으로 표시됩니다.

> 취소한 건은 **되살릴 수 없습니다.** 다시 반영하려면 **새로 등록**해야 합니다(작성중만 확정할 수 있기 때문).

#### A.4.3 삭제하기

- **작성중** 건에서만 가능합니다. 확인창(`되돌릴 수 없습니다.`) 후 목록에서 사라집니다.
- **확정된 건은 삭제할 수 없습니다.** → *"확정된 건은 삭제할 수 없습니다. 먼저 취소하세요."*

| 메시지 | 원인 | 대응 |

#### 알려진 제약

> 아래는 **현재 구현의 제약**입니다. 운영 시 주의하세요.

1. **확정된 소진 건에 재고 거래 ID가 연결되지 않습니다.**
   확정 시 재고 차감은 정상적으로 일어나고 입출고 이력에도 기록되지만, 소진 건 자체에 저장되는 재고 거래 ID(`inventory_transaction_id`)는 **항상 비어 있습니다.** 역추적은 **재고현황 → 입출고 이력**에서 비고의 소진번호(`재고 소진 IC-…`)로 찾아야 합니다.

2. **취소 후에는 같은 건을 다시 확정할 수 없습니다.**
   확정은 작성중 상태에서만 가능하므로, 취소한 건을 되살리려면 **새로 등록**해야 합니다. 이때 소진번호가 새로 채번되어 원장·이력상 별건으로 보입니다.

3. **원가가 0원이면 확정이 막힙니다.**
   리드파워 창고에서 출고하면서 생산자를 지정했는데 그 제조사·품목 조합의 원가 구간이 없으면 원가가 0으로 저장되어 확정할 수 없습니다. 원가를 등록한 뒤 **소진 건을 한 번 수정(저장)** 해야 원가가 다시 찍힙니다. **원가 등록만으로는 기존 건의 원가가 갱신되지 않습니다.**

4. **수량은 정수 ㎡만 확정할 수 있습니다.**
   재고가 정수 ㎡ 단위로 관리되므로, 매수로 입력하면 항상 짝수 ㎡가 되어 문제가 없지만 ㎡로 홀수·소수를 직접 입력하면 등록은 되어도 **확정 단계에서 막힙니다.**

5. **메뉴가 보이지 않을 수 있습니다.**
   메뉴는 DB 기준으로 표시되며, 재고 소진관리 메뉴 등록 SQL은 **수동 적용**해야 합니다(이 프로젝트는 Flyway 가 동작하지 않습니다). 메뉴가 없으면 화면 주소로 직접 접근하거나 시스템 관리자에게 메뉴 등록을 요청하세요.
   > ⚠️ 확인 필요: 개발·운영 각 환경에 메뉴 등록 SQL(`V3.18.0`)이 적용되었는지, 그리고 역할별 접근 권한(재고현황과 동일 권한으로 복사됨)이 의도대로 부여되었는지 DB에서 확인이 필요합니다.

6. **`/sitemap` 화면에는 재고 소진관리가 표시되지 않습니다.**
   사이트맵 화면은 아직 프론트엔드 정적 메뉴 상수를 쓰는데, 거기에는 이 메뉴가 들어 있지 않습니다. 사이드바에는 정상 표시됩니다.

## 9.4 손실 관리

### 9.4.1 손실 관리 개요

출하는 정상적으로 나갔는데 **현장에 덜 도착했거나(수량부족)**, **발주와 다른 규격이 납품된(스펙오납)** 경우의 **원가 손실**을 기록하고, 제조사가 부담할 몫을 정산하는 기능입니다.

> **핵심 원칙 — 매출과 고객 서류는 건드리지 않습니다.**
> 손실 처리는 **리드파워 내부 원가 관리** 항목입니다. 계약금액(품대계)·계약수량·인수증·납품확인서·납품완료계 등 **고객에게 나가는 모든 것은 그대로 유지**됩니다.

#### 무엇이 바뀌고 무엇이 안 바뀌는가

| 대상 | 손실 등록 시 |
|------|-------------|
| 발주(납품요구) 수량·금액 | **변경 없음** |
| 출하 수량 | **변경 없음** (출하 품목 비고에 손실 표기만 추가) |
| 매출(품대계) | **변경 없음** |
| 고객 서류(인수증·납품확인서·완료계) | **손실 내용이 표시되지 않음** |
| 납품률 · 잔여수량 · 출하 수량 가드 · 기성청구 | **계산할 때만** 손실분을 뺌 |
| OEM(제조사) 지급액 | 제조사 부담분만큼 **월별 매출원장에서 차감** |
| 재고 | 등록 시 **선택한 경우에만** 조정 |

원장 수량을 고치지 않고 **계산 시점에만 빼기** 때문에, 손실을 등록하면 **계약 잔여수량이 그만큼 되살아납니다.** 부족분 재발송(보전)은 **평소와 똑같이 발주 → 출하** 로 내보내면 됩니다. 무상출하 같은 별도 개념은 없습니다.

#### 손실 유형 (2종)

| 유형 | 코드 | 상황 | 금액 계산 |
|------|------|------|-----------|
| **덜 갔어요 (수량 부족)** | `SHORTAGE` | 보낸 것보다 현장이 덜 받음 (예: 118㎡ 보냈는데 110㎡만 받음) | 부족수량 × 원가 (+ 배송비 손실) |
| **다른 두께가 갔어요 (규격 오납)** | `SPEC_MISMATCH` | 계약과 다른 규격이 납품·시공됨 (예: 40T 계약인데 현장에 50T 가 깔림) | 오납수량 × (실납 원가 − 계약 원가) |

> 화면에는 쉬운 말로 나오고 괄호 안에 원래 용어가 붙습니다. 서류·문의 때는 **수량 부족 / 규격 오납** 으로 말하면 통합니다.

#### 용어

| 용어 | 설명 |
|------|------|
| 손실번호 | 자동 채번. `LS-YYYYMM-nnn` (예: `LS-202609-001`). 연월은 **발생일** 기준 |
| 손실 합계 | 귀책 분담의 대상이 되는 총액(= 원가 손실 + 배송비 손실) |
| 제조사 부담률 | 손실 합계 중 제조사가 질 비율(0~100%). 건별로 협의해 지정 |
| 제조사 부담액 | 손실 합계 × 부담률 |
| 리드파워 부담 | 손실 합계 − 제조사 부담액 (− 페널티) |
| OEM 지급 차감 | 월별 매출원장에서 제조사 지급액에서 빼는 금액 |
| 페널티 | 제조사와 **협의로 정하는 금액**. 자동 계산되지 않고 **수동 입력** |
| 보전(재발송) | 부족분을 다시 보내는 것. 정상 발주·출하 프로세스를 그대로 탐 |

> **부호 규칙**: 리드파워 관점에서 **손실이면 양수, 이익이면 음수**입니다. 스펙오납에서 더 싼 규격이 납품되면 금액이 음수(초록색)로 표시되며, 이는 원가 절감(이익)을 뜻합니다.

### 9.4.2 손실 등록

#### 접근 경로

손실 등록은 **손실관리 화면이 아니라 자금 상세 화면**에서 시작합니다.

1. 납품관리 → **기성청구**(`/admin/funds`) → 해당 발주의 자금 상세로 이동
2. 상단 탭에서 **OEM 지급** 탭 선택
3. 우측 **[손실 등록]** 버튼 클릭

> **[손실 등록] 버튼이 비활성인 경우** — 그 발주에 **인수증 서명이 완료된 출하(상태 완료)** 가 하나도 없는 경우입니다. 버튼 툴팁에 사유가 표시됩니다.
> - *"출하 정보를 불러오는 중..."* / *"OEM 지급 탭을 클릭하여 출하 정보를 불러오세요"* / *"인수증 서명이 완료된 출하가 없습니다"*

> 📷 [스크린샷: 자금 상세 → OEM 지급 탭 — [원가 재계산] [B급 조정] [손실 등록] [월별 매출원장] 버튼줄]

> 📷 [스크린샷: 손실 등록 모달 — 상단 안내 박스 + STEP 0~5 단계 구성 + 우측 실시간 계산 박스]

#### 단계별 조작 — 등록하기

모달 상단에는 항상 다음 안내가 표시됩니다.

> 손실 처리는 **리드파워 내부 원가 관리** 항목입니다. 매출(품대계)과 고객 서류(납품확인서·완료계)에는 **영향을 주지 않습니다**.

#### STEP 0 — 출하 선택
1. 손실이 발생한 **출하**를 목록에서 고릅니다.
2. 출하를 고르면 그 출하의 **품목과 원가 스냅샷**을 불러옵니다.
   - 실패 시 → *"출하 품목을 불러오지 못했습니다."*

#### STEP 1 — 손실 유형
1. **수량부족** 또는 **스펙오납** 중 하나를 고릅니다. (기본값: 수량부족)
2. 각 선택지 아래에 설명이 표시됩니다.

#### STEP 2 — 대상 품목
1. **출하 품목**을 선택합니다. 선택지에는 품목명과 출하 수량이 함께 표시됩니다.
2. 품목을 고르면 **계약 SKU 원가**가 자동으로 채워집니다(읽기 전용, 출하 등록 시점 스냅샷).
3. **부족 수량**(수량부족) 또는 **오납 수량**(스펙오납)을 입력합니다.
4. 스펙오납이면 **실제 납품 SKU** 와 **실납 SKU 원가** 를 추가로 입력합니다. (실납 원가는 해당 제조사의 원가 마스터를 확인해 **직접 입력**합니다.)
5. 수량부족일 때는 아래 안내 박스가 실시간으로 나타납니다.
   > **발주서와 출하 수량은 그대로 유지됩니다** (출하 104 불변, 비고에 손실 표기만 추가).
   > 납품률·잔여수량·기성청구는 손실분을 뺀 **100** 기준으로 계산되어, **계약 잔여 4** 가 되살아납니다.
   > 인수증은 실인수 100 기준으로 재발급이 필요합니다.

#### STEP 3 — 보전(재발송) 방식 *(수량부족일 때만)*

| 선택 | 의미 | 배송비 손실 |
|------|------|------------|
| **안 보냄** | 모자란 만큼 다시 보내지 않음 | 없음 |
| **따로 보냄** | 차를 한 번 더 불러 부족분만 발송 | **입력한 금액이 손실에 가산** |
| **다음 출하에 같이** | 다음에 갈 때 함께 실어 보냄 | **0원** (기존 출하 운반비에 흡수) |

- **따로 보냄**을 고르면 **배송비 손실** 입력 칸이 나타납니다.
- 보전 물량 자체의 원가는 손실에 넣지 않습니다. 보전 발주는 정상 발주로서 월별 원장에 이미 반영되므로 **여기서 또 더하면 이중 계상**이 됩니다.

#### STEP 4 — 귀책 분담 및 금액
1. **제조사 부담률(%)** 을 입력합니다(수량부족일 때만 표시). **0 / 50 / 100** 퀵버튼이 있고, 0~100 범위만 허용됩니다.
2. **페널티(협의 금액)** 를 입력합니다. 자동 계산되지 않는 **협의 사항**이므로 직접 넣습니다.
   - **즉시 상계 (OEM 지급에서 차감)** 를 체크하면 페널티도 지급 차감액에 더해집니다.
3. 스펙오납이면 **원가 차액을 OEM 정산에 반영** 체크박스가 있습니다.
4. 우측 **실시간 계산 박스**에 원가 손실/차액, 배송비 손실, 손실 합계, 제조사 부담(지급 차감), 리드파워 순손실이 즉시 표시됩니다. (최종 저장값은 **서버 계산 결과**입니다.)

#### STEP 5 — 재고 조정 및 기록
1. **재고를 함께 조정합니다** 를 체크하면 **창고**와 **조정 수량(매, 부호 포함)** 입력 칸이 나타납니다.
   - **창고는 그 출하를 만든 제조사의 것만** 나옵니다. 남의 창고 재고를 건드리지 않게 걸러집니다.
     그 제조사의 창고가 하나도 없으면 안내가 뜨고 **등록이 막힙니다**(기초정보 → 창고에서 먼저 등록).
   - **단위가 다릅니다.** 부족 수량은 **㎡**, 조정 수량은 **매** 입니다(1매 = 2㎡).
     그래서 부족 8㎡ 면 **4매** 가 자동 제안됩니다. 부족량과 같은 숫자가 아닙니다.
   - **재고는 운송(배차) 시점에 이미 빠져 있습니다.** 부족분만큼 또 빼면 **이중 차감**이 됩니다.
     제조사가 애초에 싣지 않아 물건이 창고에 그대로 있으면 **양수(+)** 로 되돌리고, 운송 중 분실·파손이면 **조정하지 않습니다.**
   - 여기서 체크하지 않았더라도, 나중에 손실 목록의 **[재고 조정]** 버튼으로 할 수 있습니다(→ 9.4.9).
2. **발생(현장 확인)일** 을 입력합니다. 기본값은 오늘입니다.
3. **정산 반영 년월** 을 지정합니다. 비워두면 **발생월** 기준입니다.
4. **발생 사유**(예: `현장 실사 결과 4매 부족 확인`)와 **비고**를 입력합니다.
5. **[등록]** 을 누릅니다. 등록된 손실은 곧바로 **확정(CONFIRMED)** 상태가 됩니다.

#### 입력 필드 설명

| 필드 | 필수 | 형식 | 설명 |
|------|:----:|------|------|
| 출하 | O | 라디오 선택 | 손실이 발생한 출하 |
| 손실 유형 | O | 라디오 선택 | 수량부족 / 스펙오납 |

| 페널티 | - | 숫자 | 협의 금액. 수동 입력 |
| 즉시 상계 | - | 체크박스 | 페널티를 OEM 지급 차감에 포함 |
| 원가 차액 OEM 정산 반영 | - | 체크박스 | 스펙오납일 때만 표시. **기본값 켜짐** |
| 재고 조정 | - | 체크박스 | 체크 시 창고·조정 수량 필수 |

| 발생(현장 확인)일 | O | 날짜 | 손실번호 채번 기준, 월별 집계 기준 |
| 정산 반영 년월 | - | 년월 | 미지정 시 발생월. **원장 차감 기준 월** |

#### 금액 계산식

**수량부족(SHORTAGE)**

```
원가 손실   = 부족수량 × 계약 SKU 원가
배송비 손실 = 별도발송이면 입력값, 그 외에는 0
손실 합계   = 원가 손실 + 배송비 손실
제조사 부담 = 손실 합계 × 제조사 부담률 ÷ 100        (원 단위 반올림)
리드파워 부담 = 손실 합계 − 제조사 부담
OEM 지급 차감 = 제조사 부담  (+ 페널티, '즉시 상계' 체크 시)
   └ 즉시 상계 시 리드파워 부담에서 페널티만큼 차감
```

**스펙오납(SPEC_MISMATCH)**

```
원가 차액 = 오납수량 × (실납 SKU 원가 − 계약 SKU 원가)
              ▲ 음수 = 더 싼 규격이 납품됨 = 원가 절감(이익)
손실 합계 = 원가 차액
OEM 지급 차감 = ('원가 차액 OEM 정산 반영' 이면 −원가 차액, 아니면 0)
                (+ 페널티, '즉시 상계' 체크 시)
리드파워 부담 = 원가 차액 − ('정산 반영' 이면 원가 차액) − 페널티
```

> 스펙오납은 **제조사 귀책 확정**으로 보아 부담률이 자동으로 100% 로 기록됩니다(화면에 부담률 입력 칸이 나타나지 않습니다).

**계산 예시 — 수량부족**

```
출하 104매 / 현장 실인수 100매 → 부족 4매, 원가 50,000원/매
  원가 손실   = 4 × 50,000 = 200,000원
  보전 방식   = 별도발송, 배송비 손실 150,000원
  손실 합계   = 350,000원
  제조사 부담률 50% → 제조사 부담 175,000원 / 리드파워 부담 175,000원
  OEM 지급 차감 = 175,000원  (월별 매출원장에서 차감)
```

#### 오류 메시지 & 대응 (등록/수정)

| 메시지 | 원인 | 대응 |
|--------|------|------|
| 기성청구에 포함된 출하입니다. 해당 기성 차수를 취소한 뒤 손실을 등록하세요. (출하번호: ○○) | 이미 기성 청구된 출하 | 기성 차수를 취소한 뒤 손실 등록 → 재청구 |
| 취소/삭제된 출하에는 손실을 등록할 수 없습니다. | 출하 상태가 취소·삭제 | 대상 출하 확인 |
| 존재하지 않는 출하이거나 접근 권한이 없습니다. shipmentId=○○ | 권한 없음 또는 삭제된 출하 | 담당자 권한 확인 |
| 출하에 연결된 제조사를 확인할 수 없습니다. 제조사를 직접 지정하세요. | 출하에 제조사(공급원) 정보 없음 | 출하의 공급원 정보 보완 |
| 해당 출하에 존재하지 않는 품목입니다. skuId=○○ | 품목 선택 오류 | 출하를 다시 선택 |
| 손실 총 수량(○ = 기존 ○ + 신규 ○)이 출하 수량(○)을 초과할 수 없습니다. skuId=○○ | 같은 출하·품목에 손실이 중복 등록되어 합계가 출하 수량 초과 | 기존 손실 건 확인 후 수량 조정 |
| 부족 수량은 0보다 커야 합니다. / 오납 수량은 0보다 커야 합니다. | 수량 0 이하 | 수량 재입력 |
| 스펙오납은 실제 납품 SKU가 필수입니다. / 스펙오납은 실납 SKU 원가가 필요합니다. | 스펙오납 필수값 누락 | 실납 SKU·원가 입력 |
| 제조사 부담률은 0~100 사이여야 합니다. 입력값: ○ | 범위 초과 | 0~100 으로 입력 |
| 재고 조정을 선택했다면 창고를 지정해야 합니다. | 창고 미선택 | 창고 선택 또는 재고 조정 체크 해제 |
| 재고 조정 수량은 0이 아닌 값이어야 합니다. | 조정 수량 0 | 부호 포함 수량 입력 |
| 조정 후 재고가 음수가 됩니다. 현재 재고: ○, 조정 수량: ○ | 재고보다 큰 차감 | 조정 수량 확인 |
| 저장에 실패했습니다. | 서버·네트워크 오류 | 잠시 후 재시도 |

> **등록 후 자동으로 일어나는 일**
> ① 출하 품목 **비고**에 `[LS-202609-001] 손실 4` 표기 추가 (**수량은 변경되지 않습니다**)
> ② 연결된 납품완료계가 있으면 **수량·납품률 재산출**(금액 불변)
> ③ OEM 예정총액(원가) 재계산
> ④ 재고 조정을 체크했다면 재고 반영
> 조달청 제출이 끝난 납품완료계는 재계산이 막혀 있어 ②가 건너뛰어집니다. 손실 기록 자체는 정상 저장됩니다.

### 9.4.4 정산 처리 — 차감 / 면제

#### 단계별 조작

1. 손실 목록에서 **미정산** 상태인 확정 건의 **[차감]** 또는 **[면제]** 버튼을 누릅니다.
2. 확인창(`LS-202609-001 건을 OEM 지급에서 차감 반영 처리하시겠습니까?`)에서 확인합니다.
3. 정산 상태가 **차감반영** 또는 **면제**로 바뀝니다.

| 버튼 | 의미 |
|------|------|
| 차감 | 제조사 부담분을 **OEM 지급에서 차감**하기로 확정 |
| 면제 | 이 건은 제조사에게 물리지 않기로 결정. **원장 차감에서 제외** |

#### 월별 매출원장과의 관계

OEM 월별 매출원장(`/admin/oem/monthly-ledger`)에서 손실은 **차감(−)** 항목으로 들어갑니다.

```
지급 예정 공급가액
  = 발주 합계 + 비출하 재고 소진 + 운송비 + 가공비  −  손실 차감
                                                       ▲ 여기
```

- 집계 대상: **손실 상태 = 확정**, **정산 상태 ≠ 면제**, **정산 반영 년월 = 조회 월**.
- 귀속: **제조사(귀책 대상)** 기준.
- **면제(WAIVED)** 로 바꾸면 그 달 원장 차감에서 즉시 빠집니다.

> **주의**: 원장 차감은 정산 상태가 **면제가 아니기만 하면** 적용됩니다. **[차감] 버튼을 누르지 않은 미정산 건도 이미 원장에서 차감되고 있습니다.** [차감] 버튼은 "확인·확정" 표시이자 수정·취소를 잠그는 장치로 이해하세요. (→ 알려진 제약 4)

#### 오류 메시지 & 대응

| 메시지 | 원인 | 대응 |
|--------|------|------|
| 확정 상태의 손실 건만 정산할 수 있습니다. | 취소된 건에 정산 시도 | 목록 새로고침 후 상태 확인 |
| 알 수 없는 정산 상태입니다: ○○ | 잘못된 요청 | 관리자 문의 |
| 정산 처리에 실패했습니다. | 서버·네트워크 오류 | 잠시 후 재시도 |

---

### 9.4.5 손실 취소

#### 단계별 조작

1. 목록에서 **[취소]** 버튼을 누릅니다.
2. 확인창 내용을 확인하고 **확인**을 누릅니다.
3. 손실 건이 취소 상태가 되고 목록에 취소선으로 표시됩니다.

**취소 시 일어나는 일**

- 출하 품목 비고에 넣었던 손실 표기(`[LS-…] 손실 4`)가 **제거**됩니다.
- 손실 기록이 삭제 처리되어 납품률·잔여·기성청구 계산에서 **더 이상 차감되지 않습니다.**
- 납품완료계 수량·납품률과 OEM 예정총액이 **재계산**됩니다.

**취소할 수 없는 경우**

| 메시지 | 원인 | 대응 |
|--------|------|------|
| 이미 OEM 지급에 차감 반영된 손실 건은 취소할 수 없습니다. | 정산 상태가 **차감반영** | 차감반영 처리 전에 취소하거나, 관리자와 협의 |
| 이미 취소된 손실 건입니다. | 중복 취소 | 목록 새로고침 |
| 취소에 실패했습니다. | 서버·네트워크 오류 | 잠시 후 재시도 |

**재고 조정도 함께 되돌아갑니다**

재고 조정을 실행한 손실 건을 취소하면, 조정했던 수량만큼 **반대 방향으로 자동 원복**됩니다. 확인창에도 원복될 수량이 함께 표시됩니다. 재고현황에서 수동으로 되돌릴 필요가 없습니다.

### 9.4.6 월별 집계 탭

#### 보여주는 것

**년월 × 제조사 × 손실 유형** 단위로 묶은 집계표입니다. **확정(CONFIRMED) 상태이면서 면제가 아닌 손실 건**만 대상으로 하며, 기준 월은 **정산 반영 년월**(미지정 건은 발생일의 월)입니다.

컬럼: **년월 · 제조사 · 유형 · 건수 · 원가 손실 · 배송비 손실 · 손실 합계 · 제조사 부담 · 리드파워 부담 · 페널티 · 지급 차감 · 미정산**

| 컬럼 | 의미 |
|------|------|
| 건수 | 그 달·제조사·유형의 손실 건수 |
| 원가 손실 | 수량 × 원가(스펙오납은 원가 차액) 합계 |
| 배송비 손실 | 별도발송 건의 배송비 손실 합계 |
| 손실 합계 | 원가 손실 + 배송비 손실 |
| 제조사 부담 / 리드파워 부담 | 귀책 분담률에 따른 각 부담액 합계 |
| 페널티 | 협의 페널티 금액 합계 |
| 지급 차감 | OEM 지급 차감액 합계 |
| 미정산 | 정산 상태가 미정산인 건수 |

- 정렬: 년월 내림차순 → 제조사 → 유형.
- 상단 요약 카드도 이 탭에서는 **집계표 기준**으로 다시 계산됩니다.

> 📷 [스크린샷: 손실관리 → 월별 집계 탭 — 년월×제조사×유형 집계표]

**원장과 비교할 때**

이 탭의 기준 월은 **정산 반영 년월**이며, 지정하지 않은 건만 **발생월**로 잡습니다. 면제(WAIVED) 건은 제외합니다.

다만 이 탭은 **미정산(PENDING) 건도 포함**하는 반면, OEM 월별 매출원장의 손실 차감은 **[차감] 처리한 건만** 반영합니다. 두 숫자가 다르면 **미정산 칸**을 먼저 보세요 — 대개 아직 [차감]을 누르지 않은 건입니다.

### 9.4.7 보전(재발송) 처리

부족분을 다시 보내는 것은 **특별한 기능이 아니라 평소의 발주 → 출하 프로세스** 입니다.

```
손실 등록 (수량부족 4매)
      ▼
계약 잔여수량이 4매 되살아남   ← 손실이 계산 시점에 차감되기 때문
      ▼
보전 발주 등록 (정상 발주)      → 입고되면 재고 +4매
      ▼
보전 출하 등록 (정상 출하)      → 기존 출하 수량 가드를 그대로 통과
      ▼
납품확인 → 인수증 발행 (평소와 동일)
```

- **무상출하 개념은 없습니다.** 보전 물량의 원가는 정상 발주로서 월별 원장에 자동 반영되므로, 손실액에는 포함하지 않습니다.
- **별도 차량으로 보내면** 그 배송비만 손실로 잡습니다(등록 시 STEP 3에서 **별도발송** + 배송비 손실 입력).
- **차기 출하에 합쳐 보내면** 배송비 손실은 0원입니다.
- 손실이 있는 출하의 **인수증은 실인수 수량 기준으로 재발급**해야 합니다. 등록 화면이 이를 안내하며, 시스템은 해당 건에 "재발행 필요" 표시를 남깁니다.

#### 보전 출하를 손실 건에 연결하기

보전 출하를 등록했다면, 그 출하를 **손실 건에 연결**해 두어야 나중에 "이 부족분은 무엇으로 메웠는가"를 되짚을 수 있습니다.

1. 손실 목록에서 수량부족 건의 **[보전 연결]** 버튼을 누릅니다.
   - 이미 연결된 건은 버튼이 **[보전됨]** 으로 바뀌며, 눌러서 연결을 확인·변경할 수 있습니다.
2. **보전 방식**(별도발송 / 차기합송 / 발주대체 등)과 **보전 상태**를 고릅니다.
3. **출하 검색** 칸에 출하번호나 사업명을 넣어 보전 출하를 찾고 선택합니다.
4. **저장**을 누릅니다.

> 📷 [스크린샷: 손실관리 → 보전 연결 모달 — 보전 방식·상태 선택 + 출하 검색]

### 9.4.8 인수증 재발행 완료 표시

손실이 있는 출하는 **인수증을 실인수 수량 기준으로 다시 발행**해야 합니다. 시스템은 손실 등록 시 해당 건에 **"재발행 필요"** 표시를 남깁니다.

1. 평소대로 **납품확인 → 인수증 발행** 절차로 인수증을 다시 뽑습니다.
2. 손실 목록에서 그 건의 **[재발행 완료]** 버튼을 누릅니다.
3. 확인창에서 **확인**을 누르면 재발행 대기 표시가 사라지고, 액션 칸에 **`재발행`** 자국과 날짜가 남습니다.

> ⚠️ 이 버튼은 **"다시 뽑았다"는 기록일 뿐** 인수증을 대신 발행해 주지 않습니다. 실제 재발행을 먼저 하세요.

### 9.4.9 재고 조정

#### 언제 필요한가

재고는 **운송(배차) 시점에 이미 빠져 있습니다.** 그래서 손실이 났다고 무조건 재고를 더 빼면 **이중 차감**이 됩니다. 조정 방향은 **원인에 따라 달라지므로 실물을 확인한 뒤 판단**해야 합니다.

| 원인 | 창고의 실제 상태 | 조정 |
|------|-----------------|------|
| 제조사가 애초에 싣지 않았다 | 물건이 창고에 그대로 있음 | **+ 늘림** (빠진 만큼 되돌림) |
| 운송 중 분실·파손 | 창고에서는 정상 출고됨 | **조정 불필요** |
| 보전분이 들어왔다 나가며 생긴 차이 | 차이분만큼 어긋남 | **차이분만** |

#### 단계별 조작

1. 손실 목록에서 **[재고 조정]** 버튼을 누릅니다. (확정 상태이고 아직 조정하지 않은 건에만 나타납니다)
2. **조정 대상 창고**를 고릅니다. **그 제조사의 창고만** 나옵니다.
   - 그 제조사의 창고가 없으면 안내가 뜨고 진행이 막힙니다. 기초정보 → 창고에서 먼저 등록하세요.
3. **+ 늘림 / − 줄임** 을 선택하고 **수량(매)** 을 입력합니다.
   - 부족량을 **매로 환산한 값**이 **+ 늘림**으로 제안됩니다(부족 8㎡ → 4매). 위 표에 따라 **직접 판단**하세요.
   - 입력 아래에 **㎡ 환산 결과가 즉시 표시**됩니다.
4. 필요하면 **사유**를 적습니다.
5. **조정**을 누릅니다.

> 📷 [스크린샷: 손실관리 → 재고 조정 모달 — 창고·부호·수량·환산 표시]

#### 단위 — 매수로 넣고, ㎡ 로 반영됩니다

입력은 **매수**, 재고는 **㎡** 로 관리됩니다(**1매 = 2㎡**). **시스템이 자동으로 환산**하므로 직접 곱하지 마세요. 모달이 환산 결과를 미리 보여줍니다.

#### 기록과 되돌리기

- 입출고 이력에 **`[손실 LS-…]`** 와 사유가 함께 남아 나중에 사유를 역추적할 수 있습니다.
- **손실을 취소하면 조정도 자동으로 원복**됩니다.
- 한 손실 건에 대해 재고 조정은 **한 번만** 할 수 있습니다. (이미 조정한 건은 버튼이 사라지고 `재고 +4매` 자국이 남습니다)

---

#### 알려진 제약

> 아래는 **현재 구현의 제약**입니다. 운영 시 주의하세요.

1. **[차감] 을 누르기 전에는 원장에서 빠지지 않습니다.**
   등록만 해 두고 미정산(PENDING)으로 두면 **제조사 지급액은 그대로**입니다. 실제로 지급액에서 빼려면 반드시 **[차감]** 을 눌러야 합니다.
   반영 년월을 지정하지 않고 [차감]하면 **발생월**로 자동 지정됩니다.

2. **월별 집계 탭과 원장 차감액은 같지 않을 수 있습니다.**
   월별 집계는 **미정산(PENDING) 건도 포함**하지만, 원장 차감은 **[차감] 처리한 건만** 반영합니다. 두 숫자가 다르면 대개 **미정산 건이 남아 있다는 뜻**입니다 — 집계표의 **미정산** 칸을 확인하세요.

3. **[차감] 처리하면 더 이상 수정·취소할 수 없습니다.**
   차감반영된 건은 **[수정]·[취소] 버튼이 사라집니다.** 금액·수량을 고칠 일이 있다면 **차감 전에** 끝내야 합니다. 이미 차감한 건을 고쳐야 한다면 관리자와 협의하세요.

4. **재고 조정은 한 손실 건당 한 번뿐입니다.**
   잘못 조정했다면 **손실을 취소**하거나(조정도 함께 원복됩니다), **재고현황에서 수동으로 반대 조정**을 해야 합니다.

5. **기성청구된 출하에는 손실을 등록할 수 없습니다.**
   기성 차수에 포함된 출하는 수량 정정이 청구액과 어긋나므로 차단됩니다. 그 차수를 **취소한 뒤** 손실을 등록하고 **재청구**해야 합니다.

6. **실납이 더 비싼 스펙오납은 지급 차감이 잡히지 않습니다.**
   실납 규격이 계약 규격보다 비싸면 차감액이 음수(= 제조사 지급 증액)가 되므로, 시스템이 **OEM 정산 반영을 건너뜁니다.** 손실 자체는 기록되지만 지급액은 그대로입니다. 증액이 필요한 사안이면 **원장에서 별도로 협의·처리**하세요.

#### 처리 순서 — 무엇을 먼저 해야 하나

```
① 손실 등록
     ▼
② [수정]              ← 잘못 넣은 수량·금액 정정
     ▼
③ 인수증 재발행       ← 실인수 기준으로 다시 발행
     ▼
④ [재발행 완료]       ← 다시 뽑았다는 기록
     ▼
⑤ [보전 연결]         ← 부족분을 메운 출하 연결
     ▼
⑥ [차감] 또는 [면제]  ← 이후 수정·취소 불가
```

**[재고 조정] 은 이 순서에 걸리지 않습니다.** 실물을 확인한 시점에 언제든 하면 되고, 방향은 원인에 따라 ± 입니다.

9. **메뉴가 보이지 않을 수 있습니다.**
   손실관리 메뉴도 DB 기준이며 등록 SQL(`V3.14.1`)을 **수동 적용**해야 합니다.
   > ⚠️ 확인 필요: 개발·운영 각 환경에 메뉴·권한 SQL이 적용되었는지 확인이 필요합니다. SQL 기준 권한은 시스템관리자(읽기/쓰기/수정/삭제), 리드파워담당자(읽기/쓰기/수정, 삭제 불가)입니다.

# 10. FAQ 및 문제해결

## 10.1 자주 묻는 질문

### 발주 / 계약 관련

**Q: PDF 업로드 후 정보가 정확하게 추출되지 않습니다.**
> A: AI/OCR 추출은 PDF 품질에 따라 정확도가 달라질 수 있습니다. 추출 후 반드시 정보를 확인하고 필요 시 수동으로 수정하세요. 텍스트가 없는 스캔 PDF는 추출 정확도가 떨어집니다.

**Q: "PDF 처리 완전 실패: 어떠한 데이터도 추출할 수 없습니다." 가 뜹니다.**
> A: 손상되었거나 텍스트가 전혀 없는 PDF일 수 있습니다. 다른 PDF로 다시 시도하거나, 발주 정보를 수동 입력하세요. (참고: PDF만 업로드 가능, 파일 크기 100MB 이하)

**Q: 변경계약을 등록했는데 본계약과 연결되지 않습니다.**
> A: 변경계약 등록 시 **상위 계약** 필드에서 반드시 본계약을 선택해야 합니다. 선택하지 않으면 별도의 본계약으로 등록됩니다.

**Q: 완료된 발주를 수정하려는데 안 됩니다.**
> A: 발주가 **완료(COMPLETED)** 상태가 되면 수정·삭제·출하등록이 모두 제한되며 조회·PDF 다운로드만 가능합니다.

### 출하 관련

**Q: 출하 수량을 변경하고 싶은데 변경 버튼이 비활성화되어 있습니다.**
> A: 해당 출하가 이미 **기성금 청구에 포함**되었거나 **납품확인 완료(COMPLETED)** 상태이면 수량 변경이 불가능합니다. 수량 조정(추가변경)은 출하가 **진행중(IN_PROGRESS)** 일 때만 가능합니다.

**Q: 출하를 삭제하려는데 "완료된 출하는 취소할 수 없습니다." 가 뜹니다.**
> A: 납품확인이 완료된 출하는 취소·삭제할 수 없습니다. 또한 출고요청(dispatch)이 걸려 있는 출하도 제약이 있습니다.

**Q: 출하 등록 시 "OEM 제조사를 선택해주세요." 가 뜹니다.**
> A: OEM 생산 품목 출하는 제조사 선택이 필수입니다. 제조사를 지정한 뒤 다시 등록하세요. 단, **출고요청이 진행 중인 출하는 OEM 제조사를 변경할 수 없습니다.**

**Q: "출하수량이 발주 잔여수량을 초과" 합니다.**
> A: 출하 수량 합계는 발주 수량을 넘을 수 없습니다(발주수량 ≥ Σ출하수량). 잔여수량 범위 내에서 출하하세요.

**Q: "수요기관번호가 5자리 미만입니다" 로 출하번호 생성이 안 됩니다.**
> A: 출하번호는 수요기관번호를 기반으로 생성됩니다. 발주의 수요기관번호가 올바르게 입력되어 있는지 확인하세요.

### 납품확인 (모바일) 관련

**Q: 모바일에서 납품확인 URL에 접속이 안 됩니다 / "유효하지 않은 접근 링크입니다."**
> A: URL 유효기간(24시간)이 지났거나 토큰이 만료되었을 수 있습니다. 관리자에게 요청해 새 URL을 발송받으세요.

**Q: 납품 완료가 안 되고 "현장소장 서명이 필요합니다." / "납품 사진이 필요합니다." 가 뜹니다.**
> A: 납품확인 완료에는 **인수자(현장소장) 서명 + 사진 최소 1장** 이 모두 필요합니다. 서명과 사진을 등록한 뒤 완료 처리하세요.

**Q: 사진을 더 올리고 싶은데 "사진은 최대 5장까지 업로드 가능합니다." 가 뜹니다.**
> A: 출하(납품)당 사진은 최대 5장입니다. 기존 사진을 교체하거나 일부를 삭제한 뒤 추가하세요.

**Q: 서명/사진을 수정하려는데 "이미 완료된 납품에는 사진을 추가할 수 없습니다." 가 뜹니다.**
> A: 납품확인이 완료된 건은 수정이 제한됩니다. 관리자에게 문의해 처리 방법을 확인하세요.

**Q: 문자(서명 URL)가 안 갑니다 / "인수자 연락처가 등록되지 않았습니다."**
> A: 운송장에 인수자 연락처가 등록되어 있어야 서명 URL을 발송할 수 있습니다. 운송 정보에서 인수자 연락처를 먼저 입력하세요.

### 기성금 / 기성차수 관련

**Q: 기성금 청구 시 일부 출하가 목록에 표시되지 않습니다.**
> A: 다음을 확인하세요. ① 해당 출하의 납품확인(인수증)이 완료되었는지 ② 이미 다른 기성 청구에 포함되었는지. (인수증 미완료/이미 청구된 출하는 선택할 수 없습니다.)

**Q: "이미 기성 청구된 출하입니다." / "인수증이 완료되지 않은 출하가 포함되어 있습니다." 가 뜹니다.**
> A: 기성 차수에는 **납품확인(인수증) 완료된, 아직 청구되지 않은 출하** 만 포함할 수 있습니다.

**Q: 기성 차수를 삭제할 수 없습니다.**
> A: 기성 차수는 **마지막 차수만 삭제 가능** 하며, **납품확인서가 연결된 차수는 삭제할 수 없습니다.**

**Q: "납품완료된 발주는 기성금 청구가 불가능합니다. 잔금 등록을 이용하세요." 가 뜹니다.**
> A: 납품완료 처리된 발주는 더 이상 기성금 청구를 할 수 없습니다. 남은 금액은 **잔금 등록** 으로 정산하세요.

### 자금 (선급금 / 잔금 / OEM) 관련

**Q: 선급금을 다시 신청하고 싶습니다.**
> A: 선급금은 **1회만 신청 가능** 합니다. 금액 변경이 필요하면 요청 상태에서 수정하거나 관리자에게 문의하세요.

**Q: "기성청구가 등록되어 있어 선급금 신청이 불가능합니다." 가 뜹니다.**
> A: 이미 기성청구가 진행된 발주는 선급금을 새로 신청할 수 없습니다. 선급금은 통상 계약 초기(첫 출하 전후)에 신청합니다.

**Q: 선급금을 삭제할 수 없습니다 / "입금확인이 완료된 선급금은 삭제할 수 없습니다."**
> A: **입금확인(PAID) 전** 상태의 선급금만 삭제할 수 있습니다. 삭제 시 관련 PDF도 함께 삭제됩니다.

**Q: 잔금 등록 버튼이 보이지 않습니다.**
> A: 잔금등록 버튼은 **납품완료 상태 + 잔금 미등록 + 잔금 미입금** 일 때만 보입니다. 납품완료 전이면 먼저 **[납품완료 처리하기]** 를 진행하세요.

**Q: OEM 지급을 자금 탭에서 등록하려는데 버튼이 없습니다.**
> A: OEM 지급 등록·완료는 **제조생산 > 월별 매출원장**(`/admin/oem/monthly-ledger`)에서 관리합니다. 자금 상세의 OEM 탭은 **조회 전용**(원가 재계산·B급 조정만 가능)입니다.

**Q: OEM 지급 예정액은 어떻게 계산되나요?**
> A: 기본적으로 **기성금 누계 × 70%** 입니다. 원가가 변동되면 OEM 탭에서 **[원가 재계산]** 으로 예정총액을 현재 원가에 맞게 갱신할 수 있습니다.

**Q: 수금률이 100%가 안 되는데 자금 상태가 완료로 안 바뀝니다.**
> A: 자금은 **선급금·기성금·잔금이 모두 입금확인(PAID)** 되어야 완료(COMPLETED)로 전환됩니다. 미입금 항목이 있는지 확인하세요.

### 검색 / 날짜 관련

**Q: 방금 등록했는데 목록에 안 나옵니다.**
> A: 화면 위쪽 **기간**을 먼저 보세요. 기본값은 1년 전 ~ 오늘입니다. 종료일이 오늘보다 앞이면 방금 등록한 건이 빠집니다. **[1개월]** 같은 프리셋을 눌러 다시 잡거나, 종료일을 오늘로 맞추세요.

**Q: 1년보다 오래된 자료를 보고 싶습니다.**
> A: 달력에서 **연도**를 직접 눌러 시작일을 더 앞으로 당기면 됩니다. 조회 기간에 상한은 없습니다.

**Q: 목록의 날짜가 실제보다 하루 이르게 나옵니다. / 오전에 조회하면 그날 것이 안 나옵니다.**
> A: **2026-09-17 수정 완료된 문제**입니다. 시스템은 시각을 세계표준시로 저장하는데, 일부 화면이 한국 시간으로 바꾸지 않고 그대로 보여주고 있었습니다. 그래서 한국시간 **오전 9시 이전**에 등록한 자료가 전날 것으로 보이거나 검색에서 빠졌습니다. 접근로그 · 문자 히스토리 · 출고요청 · 오류게시판 · 자금관리 · 재고 입출고이력 · 사용자관리가 해당했고, 지금은 표시와 검색이 모두 한국 시간 기준으로 일치합니다. 과거에 등록된 자료도 다시 조회하면 바른 날짜로 보입니다.

**Q: 종료일에 오늘을 넣으면 오늘 등록한 것도 포함되나요?**
> A: 포함됩니다. 종료일은 **그날 하루 전체**(한국시간 24시까지)를 포함합니다.

### 권한 / 로그인 관련

**Q: "권한이 없습니다 / 접근 권한이 없습니다." 가 뜹니다.**
> A: 해당 기능에 대한 권한이 없는 계정입니다. 자금·기성 관리는 시스템관리자·리드파워담당자만 접근할 수 있습니다. 관리자에게 권한을 요청하세요.

**Q: 로그인 직후 일부 화면(메뉴/알림)이 잠깐 비거나 새로고침하면 정상입니다.**
> A: 로그인 직후 일부 초기 요청이 인증 완료 직전에 먼저 나가면서 일시적으로 비어 보일 수 있습니다. 새로고침하면 정상 동작합니다. (자가 복구되는 현상으로 기능에는 지장 없음) *(확인 필요: 향후 인증 부트스트랩 순서 보완 예정)*

## 10.3 문제해결 시나리오 ("이럴 땐 이렇게")

### 시나리오 1 — 잔금 등록 버튼이 안 보여요

1. 잔금 탭의 **납품완료 상태** 가 "완료" 인지 확인합니다.
2. "미완료" 라면 먼저 **[납품완료 처리하기]** 버튼으로 납품완료를 진행합니다. (모든 출하 납품확인 완료 + 양측 서명 필요)
3. 납품완료 후에도 안 보이면 이미 잔금이 등록되었거나 입금완료된 상태입니다. 잔금 등록 상태/입금일 표시를 확인하세요.

### 시나리오 2 — 잔금 금액이 예상과 달라요

1. 상단 요약 카드에서 **계약총액 / 선급금 / 기성금 누계** 를 확인합니다.
2. `잔금 = 계약총액 − 선급금 − 기성금누계` 로 직접 검산합니다.
3. **선급금 차감액** 이 표시되면, 미정산 선급금이 잔금에서 차감되어 **실수금액** 이 줄어든 것입니다(정상).
4. 그래도 다르면 기성금 청구 누계가 최신인지, 변경계약으로 계약총액이 바뀌었는지 확인합니다.

### 시나리오 3 — OEM 예정총액이 실제 원가와 안 맞아요

1. 자금 상세 → **OEM 지급** 탭으로 이동합니다.
2. 상단에 노란 **재계산 경고 배너**("OEM 원가가 변경되어 재계산이 필요합니다")가 있는지 확인합니다.
3. 배너의 **[원가 재계산]** 으로 변경 전/후 금액을 확인하고 실행합니다.
4. 실제 지급 관리는 **월별 매출원장** 에서 진행합니다.

### 시나리오 4 — 모바일 납품확인 링크가 만료됐어요

1. 사용자에게 "유효하지 않은 접근 링크" 메시지가 보이는지 확인합니다.
2. 관리자 화면(운송/납품확인)에서 해당 건의 **서명 URL을 재발송** 합니다. (유효기간 24시간)
3. 인수자 연락처가 비어 있으면 운송장에 연락처를 먼저 입력해야 발송됩니다.

### 시나리오 5 — 기성금 청구 목록에 출하가 안 나와요

1. 그 출하의 **납품확인(인수증)이 완료** 되었는지 확인합니다(미완료면 청구 불가).
2. 이미 **다른 기성 차수에 포함** 되었는지 확인합니다(중복 청구 불가).
3. 발주가 이미 **납품완료** 상태면 기성금 대신 **잔금 등록** 으로 정산합니다.

### 시나리오 6 — 화면이 비어 보이거나 권한 오류가 나요

1. 먼저 **새로고침(F5)** 합니다. (로그인 직후 일시적 현상일 수 있음)
2. "접근 권한이 없습니다" 가 계속되면 본인 계정 권한을 관리자에게 확인합니다.
3. "세션이 만료되었습니다" 면 **다시 로그인** 합니다.
